# Stage 6：Olist 後期來源搜尋與替代資料可用性

查核日期：2026-10-27（Asia/Taipei）。**本輪未找到可依交接清單驗收、直接延續原 Olist 匿名顧客的後期公開資料。建議優先驗收 UCI Online Retail II，另開「回溯跨期 RFM」研究。** 已確認來源頁、資料字典、授權及下載入口，但尚未下載完整候選資料、核算資料品質或建立新 RFM。

這不是「網路上絕對不存在」的結論。範圍包含 Olist 發布者的 Kaggle 資料／公告、官方 API 文件，以及 UCI、dunnhumby、REES46 原發布者資料；一般搜尋結果只作尋路，未將第三方重製檔或新上傳日期當成新增交易。查核摘要與 HTTP 實測見[來源報告](../reports/stage6/rfm_public_source_search.json)，需求依[交接清單](templates/rfm_temporal_handoff/README.md)。

Kaggle 資料頁在網頁工具中多次回傳空本文，本機 HTTP 頁面／metadata API 回傳 404；官方 API 入門頁的直接請求亦有 502／逾時。上述限制已保留，不能用請求失敗推論資料集下架或不存在。可讀的發布者公告、官方文件索引、既有本機來源與本輪搜尋，均未提供合格的 Olist 延伸包；本輪也未取得可窮盡列出發布者所有版本的清冊。

要真的延續 Olist，仍須取得授權後期資料及同匿名 ID 的可追溯對照，再依原 P0 清單驗收。現階段可接受的新增 Olist 快照仍為 **0**。

UCI 的發票列不能直接當作獨立訂單數，商品金額須按數量與單價處理並先決定取消／退貨規則；也不能沿用 Olist「最終 delivered 且送達早於 T」的資格，因為是不同業務與欄位。以上新資料均無 Olist 身分對照，不能合併顧客或直接比較相同群組的轉移。

dunnhumby 的[網站條款](https://www.dunnhumby.com/terms-and-conditions/)帶有研究／個人／非商業等條件；本輪沒有取得資料包內的專屬授權，所以不標為 CC0、CC BY 或可自由再散布。REES46 兩個官方頁面的期間差異亦保留為待核問題，不替它選一個較長期間。

## 建議的下一步

1. 優先取得 UCI Online Retail II 完整官方包到 `shop` 專案內的 `data/raw/online_retail_ii/`，保存下載日期、來源頁／授權、SHA-256、檔案清冊及版本。這輪只有探測片段，沒有完整包，不可直接開始建 RFM。
2. 只做品質與時間覆蓋盤點：逐表／工作表筆數、實際最早／最晚日期、月別覆蓋、CustomerID 缺值、發票鍵與跨表重複、取消前綴、負數量／非正價格、幣別與金額對帳。官方命名與實體欄名需逐一核對，不預設完全相同。
3. 根據驗收結果另寫規格：用發票層級定義 F、明確區分毛購買額與退貨／調整後金額；缺顧客鍵、未知及隔離別刪掉後隱藏。兩期維持同長窗口、保留新進／退出與零活動者，再另報同 ID 交集；正式 S／T、後續 H／C、門檻與讀取政策待驗收後凍結。
4. 把早期區間作開發、後期結果區間先封存；本輪已檢視公開資料字典與下載片段，不能宣稱資料完全未曝光。固定切點套後期與重新估切點分成不同問題，不套用 Olist 數值切點或把 G3 的 90%／0.80 門檻直接當跨期成功標準。

原 Olist G3 結論與 25 個小組、1,791 位回購顧客支援不足的限制保留。新研究不會消除舊研究限制，也不會產生新的 Olist 成績。Stage 4 每日 10% 提醒預算與 Dashboard 暫緩維持。

## 本機檔案與查核界線

所有本輪新增檔案都在 `E:\kai_work\kai自己的\shop` 內。公開摘要在 `docs/`、`reports/stage6/`；HTTP 紀錄、頁面副本、兩份二進位片段與查核腳本在 Git 忽略的 `shop-mysql-runtime/verification/rfm-public-source-search/`。`.runtime` 仍指向同一個專案內目錄，沒有建立外部目錄、下載完整資料集或安裝套件。

UCI 伺服器對 Range 請求回 HTTP 200，程式僅讀取 4,096 bytes 後關閉；REES46 回 206 並提供 Content-Range。兩者只能證明入口能回傳相符的容器開頭，**未驗證完整檔案 checksum／解壓、所有欄位、實際資料量或品質**。dunnhumby 未送出申請；Kaggle／Olist 的直接存取失敗如實留存，沒有以失敗當作不存在的證據。這輪不執行新分群、訓練或保留測試評估。
