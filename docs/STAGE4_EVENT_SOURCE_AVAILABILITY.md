## 未來來源的驗收契約與停止條件

| 驗收面向 | 最低要求 |
| --- | --- |
| 訂單事件 | order_id或可稽核映射、事件種類、occurred_at、observed_at及來源識別；只能使用occurred_at<t且observed_at<t的歷史事件 |
| 承諾版本 | 承諾值、版本鍵、生效時間與取得時間、修訂／撤銷關係；在observed_at<t版本中取effective_at≤t且當時仍有效者 |
| 時間語義 | 證明時區、精度、同`t`邊界與回寫方式；列缺失、解析失敗、事件逆序、晚到與重試；未來生效的承諾可提前公告，不一概視為逆序 |
| 連接與版本品質 | 檢查匿名ID映射、孤兒join、重複／衝突、版本序列與有效區間重疊，保留不可改寫的來源追溯 |
| 歷史範圍與涵蓋 | 提供開發月份及回溯窗口的保留範圍；分開報73,254母體、可join事件、可驗證as-of查詢與已確認真實事件分母，再核逐月／路線／待件涵蓋與取得延遲 |
| 全量快照替代方案 | 若只有不可改寫全量快照，另驗captured_at、available_at<t、完整性與間隔；只能重建當時狀態，不能冒充精確取消發生時刻；單一最終快照不通過 |

此處`t`是**目前查詢的核准時間**，不是每張歷史訂單自身的核准時間；歷史取消可以發生在該單核准之後、但早於後續查詢`t`。核對來源時不能用錯時鐘而得到假的零涵蓋。

目前缺口列為**待資料**：需由可授權的歷史來源提供事件／版本匯出、來源時間語義與匿名ID對照，再按上表驗收。沒有新來源就停止本方向的訓練準備，不再拆同三個開發月、加比例或用最終status製造當時資訊。若資料驗收通過，才另行凍結原101只加一欄、五種子、每日10%及相同成熟訓練／選模契約的成對實驗。
