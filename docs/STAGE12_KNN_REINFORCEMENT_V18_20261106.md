# Stage 12：兩個高成本細層的補樣與負載觀測

本輪針對 `1101/n4/v4` 與 `1101/n5/v4` 增加不同查詢樣本，並在循序重測時同步保存系統負載。資料來自已曝光 validation，屬工程成本驗算；不新增主要訓練、完整 validation 或保留測試，T_plan 未設定。

## 母體、歷史與可選容量

完整核對 166,897 筆結構名冊、55 個非空細層及 218 個歷史不同身分。可比較成本共有 156 個不同查詢；兩個目標格各只有原 48 筆中的一個查詢，均有三次舊觀測。新增樣本須排除全部歷史身分，不能只排除具有分項計時的樣本。

| 細層 | 母體 | 歷史排除 | 可選新查詢 | 既有可比較樣本／觀測 |
| --- | ---: | ---: | ---: | ---: |
| `1101/n4/v4` | 5,615 | 7 | 5,608 | 1／3 |
| `1101/n5/v4` | 4,221 | 3 | 4,218 | 1／3 |

`1101/n4/v4` 排除 V3 的六筆與原 48 筆中的一筆；`1101/n5/v4` 排除 V3 的兩筆與原 48 筆中的一筆。結構投票欄是上界，兩格全部查詢均超過 500 位鄰居，因此不得把上界當成實際 SQL 取列量。

盤點前後核對 297 份必要來源，每輪共 99,477,212 bytes，並對回 360 筆既有成本觀測；本階段沒有重讀大型模型或原始資料。新增選樣與排名均為 0。細層覆蓋維持 55／55；本輪目的在增加格內樣本厚度。下一步封存各四筆新查詢、各一筆歷史對照與三輪循序重測規格。[完整盤點收據](../reports/stage12/retailrocket_session_knn_v18_reinforcement_inventory_20261106.json)

## 固定補樣與三輪重測規格

每格固定新增 **4 個**未驗身分，另保留原 48 筆中的 **1 個**舊樣本作對照；共 **8 新＋2 舊＝10 個不同查詢**。新樣本排除全部 218 個歷史身分後，依固定前綴 `k1-reinforcement-v18-20261106` 加 NUL 與身分 SHA 原始 bytes 雜湊，各格取最小四個，雜湊同值再按原始 ordinal；合併後依原 ordinal 執行。不得以預測、標籤或實測耗時挑樣，亦不換種子或遞補。

先完整掃描名冊、核對容量與既有對照，再以另一套字面邊界分類及完整排序獨立核對。封存十筆名單後，才抽取七路對齊資料。相同十筆按同一順序循序執行 **3 次**，每次使用新唯讀連線與 checkpoint；共 **30 次工程核對**，保留全部次數，不按耗時剔除暖機或追加較快結果。

排名沿用原 V4、分項計時沿用 V6；逐筆核對完整鄰居池、精確分數與同分排序、第 500 位切點、入選會員大小、實際投票列數及四臂輸出。三份帳本須逐位元組相同，兩筆舊對照還須對回 V6 的科學 payload；外層子集 ordinal 改變不算科學內容改變。

## 負載觀測與波動解讀

每次驗證入口使用一個背景觀測器，目標間隔 **200 毫秒**，另存首尾快照；包含準備、逐筆查詢／append 及尾端。保存實際單調時鐘、UTC 與取樣耗時，記錄全系統 CPU、可用記憶體、可取得的磁碟讀寫累積量、工作程序 CPU／RSS，以及名稱以 `ollama` 開頭的程序 CPU／RSS。程序以 PID 與建立時間區分，不讀命令列或提示內容。

第一筆 CPU 值沒有前一觀測區間，不納入摘要。每輪須有順序正確、涵蓋入口的首尾快照、至少兩個有效 CPU 區間與有效記憶體值；磁碟或程序讀取失敗明列狀態，不能補為零。實際採樣可能因排程延後，須報告間隔與缺漏。系統 CPU 包含本次工作，不代表背景程序專屬負載。

負載只對應整輪入口，200 毫秒取樣不足以定位某個短查詢或 SQL 的原因。各查詢先算三次成本的最小／中位／最大值，再比較同一查詢最快與最慢兩次的 verify、append 與內含投票變化；新樣本與舊對照分列，格內摘要每個身分等權。V6 舊對照與本次另列，不能把跨窗口差異當成優化加速。觀測器本身也有開銷，沒有另行扣除。

實測只允許一個重工作窗口，三輪循序執行；不啟動 Ollama 推論、不載入或卸載模型、不停止服務或修改其設定。

## 限制、停止條件與通過後計數

共用原始 **1,800 秒**絕對期限；程序樹 RSS 上限 8 GiB、執行目錄 20 GiB、可用記憶體至少 4 GiB、磁碟至少 8 GiB。來源、選樣、輸出、保存鏈、計時、必要負載紀錄、資源、期限或正常退出任一檢查失敗，就停止發布及樣本計入，保留私人證據。

只有三輪全數通過退出後核對，兩格不同查詢才各由 **1 增至 5**；可比較不同查詢由 **156 增至 164**，全部歷史不同身分由 **218 增至 226**。覆蓋維持 **55／55**，不重複計入舊對照或重測次數。本階段選樣與實測均為 0，下一步驗收工具。[封存規格](../reports/stage12/retailrocket_session_knn_v18_reinforcement_sampling_specification_20261106.json)
