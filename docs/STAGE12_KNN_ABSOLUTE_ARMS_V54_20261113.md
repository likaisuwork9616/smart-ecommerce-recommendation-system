## 三種差值分開列

第一張表保留四個非負絕對時間 `R32、R33、C32、C33`，以及每個序位的 `delta32=C32−R32`、`delta33=C33−R33`。delta 正值表示該查詢這次候選耗時較多，負值表示候選較少。

第二張表保留每臂內兩查詢的差距：

```text
r = R32 − R33
c = C32 − C33
gap = delta32 − delta33 = c − r
原始臂項：C = c，R = −r
```

兩筆 delta 與 gap 都各自對回 V53，不能只核對 gap 而漏掉共同偏移。差值守恆採絕對容差 1e−8 秒；拒絕缺漏、額外臂／序位、布林值、負絕對時間、非有限值與算術溢位。序位是嚴格整數 32／33，不接受浮點或字串替代。

每例以**該分項 gap** 的符號定向，不使用整筆 query 的 gap：

```text
定向 C 項 = sign(gap) × c
定向 R 項 = sign(gap) × (−r)
P = max(定向 C 項, 0) + max(定向 R 項, 0)
N = min(定向 C 項, 0) + min(定向 R 項, 0)
P + N = abs(gap)
某臂支持占比 = max(該臂定向項, 0) / P
```

正項支持此例差距，負項抵銷；每例各用自己的 P，不跨四例加總、平均或共用分母。占比不是原版／候選的總耗時占比。gap 為零時保留所有原始時間及臂內差距，但定向未定義、占比為 null；最大支持並列時保留兩臂。

第 2 對投票：原版序位 33 比 32 長 72.027 ms，候選則是 32 比 33 長 18.658 ms；兩臂一起支持 +90.685 ms 的差距，以原版那一臂較大。此例序位 33 的 C−R 為 −73.672 ms，不能把差距都說成候選序位 32 增時。

第 3 對投票：候選序位 32 比 33 長 58.375 ms；原版 32 也比 33 長，但只有 11.173 ms，在 `c−r` 中抵銷部分候選差距，留下 +47.203 ms。

第 4 對正重疊：原版 32／33 只差 −0.750 ms，候選 33 則比 32 長 59.280 ms，因此 gap 為 −58.531 ms。方向翻正後，候選支持 +59.280 ms、原版抵銷 −0.750 ms；不能遺失原本的負 gap 符號。

第 5 對正重疊：原版 33 比 32 長 23.297 ms，候選 32 比 33 長 14.390 ms，兩臂共同形成 +37.688 ms 差距，以原版那一臂較大。這不等於原版總耗時較多：此例兩查詢絕對時間相加，候選反而較長，總量和臂內差距回答不同問題。

來源的 bytes／SHA-256、28 個入口的 1,344 筆身分／順序／工作量，以及 V47–V53 前序結果均通過正式分析。另以標準庫直接讀原紀錄、不使用 V54 計算函式，獨立重算原始 16 個 timer、8 個 delta、4 個 gap 與各臂內差距、P／N／占比等，共 330 個數值／結構與來源欄位皆相符。正式報告產生後，`--audit` 唯讀重建完全相符。四例均保留，未新增篩選或實驗。

## 判讀限制

哪一臂有較大的正向支持，只是在上述恆等式下拆開差距，不表示該臂整體較慢，也不代表某個絕對時間異常。32／33 是不同查詢，在固定順序的不同時點執行；沒有跨次基準時，不將單個時間較長稱為「尖峰」，也不稱為隨時間上升或下降。

原分項量的是 wall time，沒有 CPU、實體 I/O、排程等待或外部負載資料。「投票與累加」同時包含 SQL 查詢取回與 Python 累加，不能只靠標籤把整段歸因於資料庫。維持暫不採用 V46 為完整入口預設。

下一步可用既有六對中同序位、同分項、同一臂的絕對時間作參照，確認這四例在各自時間分布中的位置；仍不需重跑實驗，也不把少量歷史波動直接當成解碼因果。
