## 三種差值分開列

第一張表保留四個非負絕對時間 `R32、R33、C32、C33`，以及每個序位的 `delta32=C32−R32`、`delta33=C33−R33`。delta 正值表示該查詢這次候選耗時較多，負值表示候選較少。

第二張表保留每臂內兩查詢的差距：

```text
r = R32 − R33
c = C32 − C33
gap = delta32 − delta33 = c − r
原始臂項：C = c，R = −r
```

兩筆 delta 與 gap 都各自對回 V53，不能只核對 gap 而漏掉共同偏移。差值守恆採絕對容差 1e−8 秒；拒絕缺漏、額外臂／序位、布林值、負絕對時間、非有限值與算術溢位。序位是嚴格整數 32／33，不接受浮點或字串替代。

每例以**該分項 gap** 的符號定向，不使用整筆 query 的 gap：

```text
定向 C 項 = sign(gap) × c
定向 R 項 = sign(gap) × (−r)
P = max(定向 C 項, 0) + max(定向 R 項, 0)
N = min(定向 C 項, 0) + min(定向 R 項, 0)
P + N = abs(gap)
某臂支持占比 = max(該臂定向項, 0) / P
```

正項支持此例差距，負項抵銷；每例各用自己的 P，不跨四例加總、平均或共用分母。占比不是原版／候選的總耗時占比。gap 為零時保留所有原始時間及臂內差距，但定向未定義、占比為 null；最大支持並列時保留兩臂。

## 判讀限制

哪一臂有較大的正向支持，只是在上述恆等式下拆開差距，不表示該臂整體較慢，也不代表某個絕對時間異常。32／33 是不同查詢，在固定順序的不同時點執行；沒有跨次基準時，不將單個時間較長稱為「尖峰」，也不稱為隨時間上升或下降。

原分項量的是 wall time，沒有 CPU、實體 I/O、排程等待或外部負載資料。「投票與累加」同時包含 SQL 查詢取回與 Python 累加，不能只靠標籤把整段歸因於資料庫。維持暫不採用 V46 為完整入口預設。
