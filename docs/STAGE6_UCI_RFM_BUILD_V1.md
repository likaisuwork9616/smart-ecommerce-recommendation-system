## 獨立核對如何完成

建置器使用已經與原 Excel 完整核對、受來源雜湊固定的 intake SQLite 原始 `rows`；沒有讀其全檔 `unique_rows`、`coherent_candidates` 或表頭判定視圖。Python 依每個截止日建立表頭集合、八欄群及整數發票／顧客彙總。

獨立路徑不匯入建置器核心。它重新讀取原 XLSX 的 ZIP／XML，載入另一個 SQLite，再用實際八欄 SQL partition、排序及計數，獨立重建表頭、保留列、主排除原因、所有旗標、發票資格及顧客狀態／RFM。兩個路徑僅共用契約欄位與 CSV 序列化；不是將建置器的結果當期望答案。

32 份 CSV 的每個資料欄位，包括排序、null／0、布林、陣列旗標、逐列金額、去重代表列與顧客值，均完整反讀一致。另核對來源／輸出檔案 bytes 及摘要。合成測試涵蓋 T 邊界、未來衝突不可改 T1、整張隔離、零活動、千分之一金額、跨表最大重數，以及總額相同但交換顧客金額的反例。

全部保存檔案都在 `shop`，逐筆資料與執行狀態由 Git 忽略；原 Excel、前輪研究與使用者指定的 runtime 位置保留。本輪只用專案 `.venv` 的 Python 標準庫，沒有新增套件；原始、輸出與驗收證據均保存在專案內。

現有完整產物只使用：

```powershell
.\.venv\Scripts\python.exe -B scripts\build_uci_rfm_v1.py --verify
```

`--verify` 核全部已保存來源、CSV、manifest 與正式報告 hashes，**不重新算 RFM，也不重做本輪逐格核算**；本輪完整核算結果由驗收 JSON 保存。首次空白命名空間才依序使用 `--prepare`、`--run`；既有或部分資料不得刪檔後重跑。實際建置失敗會留下 failure.json 並停止，已有完整 guard 的 `--run` 只驗現有 bytes。
