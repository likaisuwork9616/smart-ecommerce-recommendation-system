# Stage 4：固定模型，拆解二月時齡退步的交集與提醒交換

前輪[等待時齡p90單欄比較](STAGE4_UNOBSERVED_HANDOVER_AGE.md)在二月由原101欄的171張延遲命中降至155張。同月SP→RJ、承諾22–30天、等待24–72小時分別淨少17／15／11張，但這些是重疊邊際，不能相加或直接當成同一群訂單。本輪只分析凍結分數，確認真正的交集與提醒名額交換。

## 固定條件與資料角色

原101欄及時齡102欄月份模型、核准時點、L2＝100、topk10與每日完整日10%預算都不變。診斷CLI不載入、重播、訓練、校準或改選模型，只核對檔案雜湊並讀取前輪138欄快取及128,112列分數帳本。前輪80候選主方案及研究適用判斷不變。

每個已結束完整日先按各模型分數遞減、訂單ID遞增排序，取`floor(0.1×N)`個提醒，再套已知答案遮罩。未知答案保留名額競爭，不當準時；各路線或交集不重排，也不各分10%。歷史答案仍要求實際送達嚴格早於各fold原月初截止。

全部12個phase保留原成熟時鐘，二月是已反覆檢視的2018-02開發回測。較早歷史與其他開發月只提供同定義對照；重複月份因截止不同，不當獨立樣本相加。原保留測試未重新評估，沒有新增未知測試成績。

## 三個群組與八個互斥格

| 位元／群組 | 定義 |
| --- | --- |
| R | `state_route == SP->RJ` |
| P | 既有承諾分箱22–30天，即`21 < estimated_delivery_days <= 30`，沿用原分箱且含21.x天 |
| A | `24 < seller_unobserved_handover_pending_age_p90_hours_90d <= 72`小時 |

群組位元固定按R／P／A排列，`111`才是三重交集；`110`表示R、P成立但A不成立，後者可能是缺值、至多24小時或超過72小時。這些位元是訂單群組身分，與前輪三模型「抓到／漏掉」位元不同。

000至111八格互斥且包含所有完整日訂單，空格也保留；ALL、R、P、A、RP、RA、PA、RPA則是可重疊的邊際。每格同時保留總訂單、已知延遲分母、原／新TP、FP、FN、兩者皆抓到／皆漏掉、補抓及新增漏報。零延遲分母的比率留空，小樣本標示不隱藏。

「新增漏報」指原101有提醒、時齡102沒有提醒的已知延遲；「兩者皆漏報」是另一群。不能把全部新模型FN都稱為這輪退步，也不能把兩個模型的共同漏報與前輪三個不同模型的共同漏報混用。

## 提醒名額交換與排名

所有排名和「排名−當日容量」都在原完整日計算，才切出交集。新增漏報分別檢查原／新排名百分位與差1–3、4–10、11+名額，不能拿不同模型的原始分數直接相減當風險變化。

每個完整日、每格記錄移除與新增提醒，格內交換為`min(移除,新增)`，流出／流入為每日差額的正部，再合計全月。不能以月淨差替代每日流量，也不把某張新增準時提醒配對成指定延遲件的擠出原因。

R、P、A及其聯集的新增漏報發生日，另列整日所有新增／移除提醒，按八格、真實路線、既有承諾與時齡分箱、答案類別對帳。這些是同日共現的聚合計數，不證明個別因果交換。A不成立的格再看既有五個時齡分箱，避免把不同情況混在一起。

### 提醒去了哪裡，漏報距離預算多遠

二月兩者容量均為641；新增／移除提醒各141個，按完整日八格對帳為格內交換53、跨格流量88。月淨提醒數增加的格只有000的+57與010的+18；它們合計75個月淨增量，不能當成每日跨格流量88。

| 二月群組 | 原提醒→新提醒 | 原TP→新TP | 原FP→新FP | 解讀 |
| --- | --- | --- | --- | --- |
| 000：三條件均不成立 | 230→287 | 27→31 | 203→256 | 多57個名額，延遲多4、準時多53 |
| 010：只有承諾條件成立 | 81→99 | 32→34 | 49→65 | 多18個名額，延遲多2、準時多16 |

110的13張新增漏報發生在九個完整日。這九天合計，兩模型各提醒203張，新增／移除各58張，整日補13、失19，淨−6；110自身淨−11，其他格合計淨+5。這九天合計SP→SP新增21／移除20、補2／失0；時齡72–168小時新增28／移除9、補7／失4，超過168小時新增11／移除5、補2／失2。路線與時齡是各自重疊的邊際，不能合成路線×時齡聯合數，也不能指認某張準時單直接擠掉某張漏報。

全月39張新增漏報中，36張落在新排名10–20%、3張在20–50%。按「新名次−當日容量」看，差1–3／4–10／11+個名額各9／15／15張，中位數8；110的13張各為2／4／7張，中位數11。三重交集三張在三種距離各一張。多數退步落在前20%，但只有9張緊鄰容量邊界；固定10%下仍須改善前段排序，不能靠多發提醒宣稱改善。

| 研究主方案 | TP413、FP1,432、FN1,229、召回25.15%、歷史下限19.63%維持；仍未達適用要求 |

不因這次事後分群直接新增RPA交互或群組配額。若下一輪要訓練，建議先保持101／時齡102的特徵、L2＝100、topk10、訓練時鐘與每日10%，用**少量事前固定的種子成對重訓**，完整報告各種子的月／路線得失與成對差異平均、範圍，不挑最佳種子。原樹設定`subsample=0.8`、`colsample_bytree=0.8`且目前只有`random_state=42`，值得先確認交換是否穩定，再決定改特徵。

這只是待驗的穩定性問題，尚未證明抽樣造成退步；相同種子搭配不同特徵維度也不能隔離抽樣因果。換種子沿用同一批資料不會產生獨立新樣本，不能包裝成未知測試進步。**本輪沒有執行新訓練**，預設原RF不變，Dashboard維持暫緩。

## 重現方式

使用原專案`.venv/`、前輪保留的資料／模型檔，不需新增套件或MySQL操作：

```powershell
.\.venv\Scripts\python.exe scripts\diagnose_age_intersections.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

來源包含前輪正式報告、診斷、規格、138欄快取與分數帳本，以及16份月份模型與3份選模產物的原檔供雜湊核對；模型不反序列化。原始資料、模型、逐筆分數與執行證明維持Git忽略，只提交程式、測試、聚合報告、文件與無輸出Notebook。
