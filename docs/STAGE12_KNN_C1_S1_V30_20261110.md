## 實作與驗收進度

| 實作 | 行為 |
| --- | --- |
| 精確 schema | exact FrozenCatalog、唯讀 MappingProxyType、tuple；全值 ASCII ID／非負 int 驗證，bool／float 不當成 int |
| 完整表示 | first／counts 全 map 按字串 ID 排序；first_times／fallback 保留全部順序、重複與零值；不快取 encoded bytes |
| 新指紋 | 明確版本 prefix＋完整 compact JSON UTF-8，再完整 SHA-256；新快照 hash 與舊版不同，來源檔 path／bytes／SHA 不改 |
| 原 C1 接合 | 原 identity／設定／model canonical 與 create／post-lock full source check 仍委派原碼；只改 snapshot digest，calls、cache.use、request 與完成收據共同綁定 scheme |
| 時間邊界 | validation／JSON／UTF-8／SHA／release 分開計時；fingerprint 在原 cold／pre-use／post-use 範圍內，每次釋放兩個子段合併列示 |

第一批已核對 exact preimage、schema／型別、map 插入順序、tuple 順序／重複、空快照／零值／大整數、修改各欄、截斷、版本域、每次 live 重算、計時守恆及 watch 失敗。這是人工 codec 核對；第一階段僅此18項通過；新 S1 pool 的原38情境、四臂及新程序發布另由下節正式合併驗收確認。

本輪尚未執行任何真實48筆比較，沒有加速比例。來源、鎖定後完整核對及獨立發布仍保留，保留測試鎖定。

人工完整窗口實際綁定 43 個來源、25 個 binding；這些是人工fixture規模，與原1261／15的檔案身分核對分開列示。新 suite使用一般及501鄰居邊界fixture，核對四臂完整payload bytes、Decimal字串、binary64 delta hex、SQL工作量與查詢順序；沒有採用C2排序改動。

validation、JSON、UTF-8、SHA及release皆有原始巢狀事件，完整時間樹可重算；每次fingerprint的release有兩個子段（rows／text與preimage bytes），都留在同一cold、pre-use或post-use完整入口內。warm C一個cold build與其餘6次hit；R沒有cache或snapshot觀測，兩臂均使用相同原細項觀測深度，沒有隱藏預載。

## 操作與證據

從專案根目錄使用`.venv`：

```powershell
.venv/Scripts/python.exe -B -m scripts.accept_retailrocket_session_knn_snapshot_v30 --audit
```

`--audit`核對既有方法／規格／測試log／全部來源與人工窗口證據，不重跑測試或建立真實比較；會讀取來源以重新計算SHA。`--acceptance`已完成，既有不可變收據會阻止覆寫。此入口沒有`--measure`，不能當成真實比較入口。
