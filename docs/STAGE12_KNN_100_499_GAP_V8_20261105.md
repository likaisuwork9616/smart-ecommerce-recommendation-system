# Stage 12｜100–499 鄰居帶的兩個缺樣細層

這一輪量測既有 K1 排名的工程成本。先找出 V6 原 48 筆及 V7 新 34 筆都沒量到的細層，再從母體最大的兩格補樣。先前批次取列候選已結案，本輪使用封存的 V4 排名與 V6 保存計時。推薦效果待全量科學驗收，預留測試鎖定。[上輪結果](STAGE12_KNN_GAP_AND_VOTE_RESULTS_20261105.md)

## 實測前固定的補樣規格

每格取 **4 筆**，共 8 個新身分。兩格各有上萬或近萬筆查詢，比前輪每格兩筆多留兩個觀測，用來看同一格內的耗時差異。這是工程診斷配額，每格四筆對稀有慢查詢的代表性仍有限。

1. 核對盤點收據、完整名冊、V3 的 64 筆、V5／V6 的 48 筆和 V7 的 34 筆。排除聯集中的 144 個身分。依原 p90 mask、鄰居數帶與投票上界帶決定資格。
2. 在每格計算 `SHA256(b"k1-gap-v8-20261105\x00" + bytes.fromhex(key_sha256))`，按 digest 位元組升冪取前四名，平手依原 ordinal。合併後按原 ordinal 排序，以完整排序獨立重算。來源、歷史身分、配額或結果不符即停止。選樣階段只讀結構與身分，選定後才讀七路原始列。
3. 以同一份封存名單、唯讀模型和 V4 四臂精確核對，使用 V6 觀測器在兩個全新保存目錄各跑一次。每次均驗證 key／ordinal、完整鄰居池 SHA、精確投票、指標、EOF、checkpoint 鏈與 query seal。這兩格的合格鄰居都少於 500，故所有鄰居都會入選，實際取回的會員列數可直接與結構上界核對。最後逐列比對兩次實體 bytes，再比對串接 SHA。
4. 兩次共用一個 30 分鐘絕對期限及原監督資源上限。要求初末來源相同、外部觀察退出碼 0，退出後獨立重算名單、逐筆費用與 ledger。失敗則保留 partial 收據。本機保留個別 key、原始列及模型，GitHub 僅發布聚合報告與指紋。

依上輪窗口，來源雜湊與七路抽取占主要時間；本次實測估 7–12 分鐘。只有 8 筆都通過，才能把有樣本細層報成 38／55、無樣本細層母體報為 5,615 筆，歷史不同已驗查詢報為 152 筆。當前規格步驟的新增選樣與工程計算均為 0 筆。[事前固定配額與執行條件](../reports/stage12/retailrocket_session_knn_v8_gap_sampling_specification_20261105.json)
