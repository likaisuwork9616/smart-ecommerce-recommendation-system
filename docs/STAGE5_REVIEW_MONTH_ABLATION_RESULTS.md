# Stage 5：移除購買月份的真實離線消融

目前適用範圍、限制、公開／私有交付與下一步見[四欄／三欄模型卡](STAGE5_MODEL_APPLICABILITY.md)。保留四欄開發對照及三欄消融證據，Stage 5維持待資料；本輪未追加訓練、重新出分或改寫以下原數字。

本頁保留前輪真實消融與交付結果。後續已完成[兩臂凍結分數的只讀診斷](STAGE5_REVIEW_ABLATION_DIAGNOSTICS.md)，沒有追加訓練；以下數字與流程維持原輪紀錄。

本輪一次真實消融及交付驗收通過，但**移除月份沒有改善開發AP**：三個月均略低於四欄，等權macro AP由0.170928降為0.170494（差−0.000434）。三欄獨立選C依序10／0.1／0.1；四欄沿用原凍結分數。

本輪依[凍結的正式入口](STAGE5_REVIEW_MONTH_ABLATION_DISPATCHER.md)執行一次三欄消融，對照沿用原四欄凍結分數。唯一特徵改動是移除 `purchase_month`；H60目標、完整角色、其餘三欄、前處理、C候選、內層選參與評估政策保持原樣。**所有結果都是2017-12、2018-02、2018-04三個已檢視月份的開發回測，沒有新增未知保留測試。**

## 固定方法與資料界線

| 項目 | 本輪沿用規格 |
| --- | --- |
| 目標與預測時點 | 核准時預測核准後60天內第一個記錄回答是否為1–2分；3–5分為另一類 |
| 未知標籤 | 無答、超窗、品質隔離及未成熟保留未知；不補成負例、不進前處理、fit或評估分母 |
| 三欄與維度 | 購買星期、購買小時、原核准等待小時；31個固定one-hot欄＋train-only標準化等待，共32維 |
| 四欄對照 | 原44維方案及既有內／外層分數、指標、C選擇均保留；本輪不重訓、不重選C或重出分 |
| 模型與選參 | 原L2 Logistic、C＝0.1／1／10；每候選獨立pipeline，按自身內層AP選C，距最大值≤1e-12時取較小C |
| 外層 | 每fold選C後另建pipeline從頭fit；不讓外層答案參與選參 |
| 全名冊出分 | query保留未知單，交給模型前清空七個未來truth欄；完整出分後才與另外保存的角色truth計分 |
| 配對與差值 | 18個完整同ID／順序／truth區塊；內層同C，外層允許兩臂自行選出不同C；差值固定三欄減四欄 |
| 固定評估 | AP、ROC-AUC、Brier、binary logloss及p≥0.5混淆表；任一方無定義的差值為null，不補0 |
| 彙總 | 三個外層月全部有效才計等權macro AP；無pooled AP、信賴區間、重新選門檻或校準 |

訓練資格按每次fit自己的時鐘判斷：`核准+60天<fit`，首答在`(核准,核准+60天]`且早於fit。全域2018-07-01的答案不能回填較早fit。內層驗證月依序2017-09、2017-11、2017-12；外層依序2017-12、2018-02、2018-04。2017-12被後一個fold重用是凍結滾動日曆的一部分，不能另算獨立驗證。

Stage 5固定random_state=42只作重現；本輪沒有五種子或每日預算排名。Stage 4仍維持待資料、每日10%及11／29／42／73／101五種子，Dashboard未開工。

## 操作與禁止重跑

本輪執行的是以下已凍結動作：

```powershell
.\.venv\Scripts\python.exe scripts\run_review_month_ablation.py --train
```

這是已完成執行的紀錄，不能當作驗證用重跑指令。已有正式報告、私有產物、失敗收據或命名空間內未知檔案時，入口會在fit前拒收；原本要求空輸出版本的`--check`／準備流程也不能拿來重建已完成版本。後續驗收應只讀現有分數、manifest及凍結來源。

Git clone不包含原Olist、H60角色、四欄分數或私有guard。缺檔或版本不同就停止，不補訓練，也不能刪除舊證據來繞過拒收。若另有訓練需求，須先明定新的單因子規格、執行版本及私有輸出位置。

## 限制與下一步

保留三欄消融作已完成的開發證據，四欄仍作原凍結對照，沒有理由因本輪結果直接替換。下一步先只讀兩臂分數，檢查逐月機率／排序差異及現有星期、小時、等待支援，確認可解釋的差異後再提出一個單因子規格，不直接追加訓練。驗證耗時改善可另版處理，須保留本次來源鏈與結果。

本輪只評估具有合格H60首答的訂單。未知／未回覆者雖完整出分，仍缺可驗證y，不能把已知子集結果外推全核准母體。滾動fold會重用歷史訂單及客戶；三個月已檢視，不能作獨立重複或未知保留測試。原入庫、評分修訂版本、上游完整性與業務時區證據仍缺，現有快照一致不等於核准當下營運可用。
