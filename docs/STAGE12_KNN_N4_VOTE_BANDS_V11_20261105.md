# Stage 12｜相同鄰居帶的兩個投票量缺口

本輪使用封存的 V4 排名與 V6 成本計時，處理剩餘母體最大的兩格。兩格都在 500–999 合格鄰居帶，投票量的結構上界卻有明顯差距。要量的是每筆查詢建立完整鄰居池、選前 500 位及累加其商品紀錄所需的工作與時間。[V10 結果與剩餘缺口](STAGE12_KNN_TWO_CAPPED_CELLS_V10_20261105.md)

本文的「會員列」指鄰居工作階段內的商品紀錄。結構上界把會員列數最多的 500 個鄰居加總。排名依相似度挑選，實際取回列數須逐筆量測。第一格恰有 500 位合格鄰居的 7 筆會全數入選，此時投票列數應等於上界，切點同分但被排除的鄰居數應為零。其他查詢容許實際投票列數低於上界。這一步新增選樣與排名均為 0 筆。[名冊、來源指紋與容量收據](../reports/stage12/retailrocket_session_knn_v11_gap_inventory_20261105.json)

## 事前補樣規格

兩格各取 **4 個新身分**，共 8 筆，沿用前三輪的配額與成本口徑。四個固定觀測可用於查看格內差異，稀有慢查詢仍有不確定性。

1. 核對盤點收據、完整結構名冊、六組歷史樣本及來源 SHA。從兩格候選中排除 168 個不同的已驗身分。
2. 每格計算 `SHA256(b"k1-gap-v11-20261105\x00" + bytes.fromhex(key_sha256))`。取 digest 按位元組排序最小的四筆，平手依原 ordinal。將兩格合併按原 ordinal 排序後，以獨立完整排序核對，再封存名單。選法只讀結構與身分，不保證恰有 500 鄰居的查詢被抽中。身分、來源、配額或排序不同即停止，保留原始收據。
3. 封存後抽取七路 validation 原始列，在兩個全新目錄各核對同批 8 筆。兩格都驗完整鄰居池 SHA、精確相似度、前 500 名的順序、切點平手及每位入選鄰居的會員列數。合格鄰居數恰為 500 時，全部入選且投票列數等於上界；超過 500 時，投票列數可低於或等於上界。另列精確因果加總次數。
4. 兩次共用同一個 1,800 秒絕對期限，沿用 8 GiB RSS／20 GiB 新目錄上限與可用記憶體 4 GiB／磁碟 8 GiB 下限。發布需核對四臂精確輸出、EOF、保存鏈與原期限，逐列比對兩份 ledger，核對總 bytes 和串接 SHA，並驗證初末來源一致、外部觀察正常退出、退出後獨立重算成功。

若全數通過，有樣本細層將從 42／55 增至 44／55，缺樣母體從 1,218 降至 533 筆，歷史不同已驗查詢數增至 176。規格階段的實際新選樣與排名均為 0 筆。[事前固定配額與驗收條件](../reports/stage12/retailrocket_session_knn_v11_gap_sampling_specification_20261105.json)
