# Stage 4：原101與時齡102的固定種子成對重訓

前輪[二月交集診斷](STAGE4_AGE_INTERSECTIONS.md)固定seed42，發現時齡102在二月補回23張、失去39張延遲，命中171→155。真正三重交集只失3張，主要獨立損失在SP→RJ、承諾22–30天、但時齡不在24–72小時的110格，補2／失13、淨−11；其他月份沒有一致出現同樣損失。本輪保持兩組特徵，只用事前固定種子成對重訓，確認退步與名額交換是否穩定。

## 訓練前固定的比較方式

種子順序固定為`[11, 29, 42, 73, 101]`，每個都訓練原101及時齡102，不以結果增刪種子，不挑最佳種子、不集成或混分數、不改選研究主方案。先保存不可覆寫的正式規格，再執行訓練。seed42也重新訓練，對照上一輪凍結帳本的分數與提醒集合，不能把既有模型載入當成新訓練。

每個種子有8個唯一月份版本：2017-07、08、09、10、11、12及2018-02、04；合計`5×2×8＝80`次fit。三個fold保留原12個phase，同一月份模型在不同歷史成熟截止可重複評估，不能把這些列當成獨立月份或新增樣本。

| 固定項目 | 定義 |
| --- | --- |
| 預測時點／訓練答案 | 核准時點；原deadline答案時鐘、wait0、相同成熟訓練身分與順序 |
| 模型輸入 | 原101，或只多待件等待時齡p90的102；不加入待件件數 |
| 樹與排序設定 | L2＝100、native topk10、400樹、depth4、learning rate0.05、min child weight10、hist、subsample0.8、colsample_bytree0.8；只改random_state |
| 前處理 | 原訓練集補值、缺失指示與類別編碼；無驗證／開發資料擬合前處理 |
| 提醒預算 | 完整日所有訂單先按分數遞減、ID遞增，取`floor(0.1×N)`；群組不另分10% |
| 歷史答案 | 實際送達嚴格早於各fold原月初截止；未知答案先競爭名額，不當準時 |
| 保留期間 | 特徵查詢與評分均限2018-05-01之前；原保留測試不重新評估 |

101是93個數值＋8個類別欄位；時齡102是94＋8。原補值器`add_indicator=True`不變，原始輸入多一欄可能讓轉換後多出時齡與自動缺失指示兩欄。這是原規則的結果，沒有手動加入額外特徵。

## 比較與統計口徑

每個種子、每個phase都保留兩模型的延遲分母、TP／FP／FN、召回、完整日提醒及未知答案提醒；另依真實路線拆分補抓、新增漏報與名額流量。二月沿用R＝SP→RJ、P＝原承諾22–30天分箱（`21 < 天數 <= 30`）、A＝`24 < 時齡小時 <= 72`，拆八個互斥格與110的五個既有時齡分箱，不重新搜尋分群邊界。

各模型的指標與每個種子的`時齡102−原101`成對差異，分別報全部五個種子的算術平均、最小值、最大值，以及成對差異為負／零／正的種子數。成對差異範圍從五個實際差異計算，不能拿兩模型各自的極值相減。分母固定時召回差可讀為百分點；延遲分母為零的群組召回留空。

每日各群組的格內交換為`min(移除,新增)`，跨群流出／流入為每日差額正部，先逐日計算再合計。月淨差不能代替每日gross流量，聚合共現不能證明指定訂單互相擠出。比較兩模型時使用相同seed，但特徵維度不同可能影響欄位抽樣與樹路徑，不能隔離出單一隨機機制的因果效果。

二月新增漏報另在內部以訂單身分比對跨種子交集／聯集、兩兩Jaccard及發生頻率，只提交聚合數字。這用來區分「整體退步方向穩定」與「每次恰好漏掉同一批訂單」，兩者不等價。原始資料、模型與逐筆帳本維持Git忽略。

## 實際結果

已實際完成80次新fit，沒有重用舊版本代替訓練，也沒有重試後挑成績。全部種子都保留；seed42的85,258筆唯一月份／模型分數、128,112列phase分數與完整日提醒集合重現前輪。正式結果見[事前規格](../reports/stage4/age_seed_stability_specification.json)與[訓練報告](../reports/stage4/age_seed_stability.json)。

## 重現方式

使用專案`.venv/`與既有Olist快取，不需新增套件或MySQL操作：

```powershell
.\.venv\Scripts\python.exe scripts\compare_age_seed_stability.py --specification-only --n-jobs 2
.\.venv\Scripts\python.exe scripts\compare_age_seed_stability.py --n-jobs 2
.\.venv\Scripts\python.exe scripts\diagnose_age_seed_stability.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

已完成的正式報告不覆寫。若要重新fit，使用新的Git忽略輸出目錄（例如`--output-dir .runtime/age_seed_reproduction`），先跑該目錄的`--specification-only`再訓練；明確中斷續跑可用`--reuse-new-versions`，只允許相同規格的本輪版本，並另記實際fit／重用次數。不要刪除或覆蓋前輪模型來重跑。

本輪是同一批歷史驗證與已反覆檢視的開發回測的種子穩定性實驗。五個種子不是五份獨立新資料，不是未知測試成績，也不足以證明新增特徵適合上線。研究主方案與預設原RF不因種子結果自動替換，Dashboard維持暫緩。
