# Stage 4：只新增未觀測交運待件等待時齡p90

前輪[未觀測交運待件件數](STAGE4_UNOBSERVED_HANDOVER_COUNT.md)未提高固定候選整體召回。本輪以原101欄作對照，單獨測等待時齡p90，不把前輪件數一起加入，區分「待件有多少」與「待了多久」的假設。

## 固定設定與唯一新輸入

| 項目 | 本輪設定 |
| --- | --- |
| 對照 | 原101欄 `xgboost_rank_backlog_7_14d_l2_100_topk_10` |
| 新候選 | 原101欄＋`seller_unobserved_handover_pending_age_p90_hours_90d`，共102欄 |
| 其他設定 | 核准時點、seed42、L2＝100、原生topk10、原樹參數與前處理規則不變 |
| 歷史資料 | 主賣家其他訂單、有效購買≤核准、核准在`[t−90天,t)` |
| 已觀測事件 | 實際交運或送達嚴格`<t`才算已知；等於t仍未知 |
| 等待時齡 | 在尚未觀測上述任一事件的待件中，計算`(t−歷史核准)`小時的linear p90；至少1筆即可 |
| 缺失 | 無待件或未知主賣家時為NaN，不填0、不合併未知賣家 |
| 訓練 | 八個月份新fit、原101八個版本重播，訓練列、穩定排序與每日query一致 |
| 提醒與選模 | 完整已結束日`floor(0.1×N)`；前79候選指標凍結，加1後共80候選，依原歷史規則選模 |

主賣家沿用最高品項單價`price`、再依最低品項序號的規則。排除本單，不讀未來送達、最終狀態或評論來預先刪除歷史待件；已觀測的矛盾事件也不進待件。此等待時齡與104欄已完成交運耗時分位不同，沒有套用後者五筆事件才可計分位的規則。

模型白名單只新增age一欄，不新增待件件數或手工缺失指示。原有`SimpleImputer(add_indicator=True)`規則維持，age缺失自然會產生對應指標；因此原始輸入101→102，轉換後欄數可能增加兩欄。補值中位數及類別編碼只能由當月成熟訓練列估計。新特徵也會改變樹的擬合與特徵抽樣，不能把特定提醒交換視為時齡的因果效果。

原137欄70,844筆快取保持原值，只追加age一欄成138欄，沒有從前輪含新待件件數的138欄再加成139。原快取中的已完成交運事件數／耗時欄仍只供診斷，不進新102欄輸入。查詢都嚴格早於2018-05-01，不替原保留測試產生新特徵或評分。

在這70,844筆查詢中，45,089筆（63.65%）有等待時齡，25,755筆為已知賣家沒有此類待件而留缺值；本資料沒有缺賣家的查詢，程式仍保留該處理分支。這是特徵覆蓋，不是模型召回。

這仍是未觀測事件代理。CSV缺取消、事件入庫與品項版本時間，靜態主賣家映射在核准時可知也是假設，不能直接解讀為貨物實際留在賣家手上的時間。

## 評估與路線得失

九個歷史phase保留原fold月初的實際送達答案成熟截止；重複月份不當成獨立樣本相加。2017-12、2018-02、2018-04為已反覆檢視的三個開發回測。未知答案先參與完整日排序，再套已知答案遮罩；每個路線、承諾、日量或時齡組不重排，也不另給10%。

診斷時齡分箱在訓練前固定為缺失或空歷史／至多24小時／24–72／72–168／超過168小時，不搜尋最佳切點。NaN在這個單欄切片不能分辨空待件與未知主賣家，品質報告另記錄原因。全部路線及提醒流入／流出保留；不同維度重疊，不把各表損失相加。

前輪三模型共同漏報仍以原101／已完成交運事件數102／交運歷史104定義，再檢查新age模型是否補回，沒有換成上一輪的待件件數模型。補抓必須與新增漏報一起解讀。固定新候選、雙候選歷史選模與完整80候選研究主方案分開呈現，不用開發或子群結果選模。排名分數是sigmoid(raw margin)，不是校準後延遲機率。

## 重現方式

使用專案`.venv/`，本輪不新增套件或MySQL操作：

```powershell
.\.venv\Scripts\python.exe scripts\delay_unobserved_handover_age_features.py
.\.venv\Scripts\python.exe scripts\train_unobserved_handover_age.py --specification-only --n-jobs 2
.\.venv\Scripts\python.exe scripts\train_unobserved_handover_age.py --n-jobs 2
.\.venv\Scripts\python.exe scripts\diagnose_unobserved_handover_age.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

原始資料、快取、模型、逐筆分數與本機驗證留在Git忽略路徑。訓練前固定規格並保存來源雜湊；特徵程式以`.gitattributes`固定LF，避免Windows Git換行轉換破壞程式來源雜湊。

中斷且尚無完整報告時，`--reuse-new-versions`可重用同規格的自有月份版本，不能算成新fit。完成產物不覆寫；重做完整實驗須另設新的Git忽略輸出目錄，將138欄快取放在該目錄的`data/olist_delay_unobserved_handover_age_features.csv`，再指定`--output-dir`。
