# Stage 4：固定 L2＝100，比較每日排序的配對焦點

前輪[排序 L2 比較](STAGE4_RANK_REGULARIZATION.md)顯示，L2＝100 改善九月，卻失去七月部分延遲提醒。本輪沿用相同 83／101 欄、成熟訓練訂單與樹模型設定，固定 L2＝100，只比較原生 LambdaRank 的 `lambdarank_num_pair_per_sample=10／20／40`，檢查七月與九月能否兼顧，也檢查其他月份與路線的代價。

方法見[訓練前規格](../reports/stage4/rank_pair_focus_specification.json)，其 SHA-256 為 `1e39729c20eb0f9af1d291e3826cd8c2d4d333f91ccfa2aa0c27254973d60464`。來源為綁定 SHA-256 的[前輪 71 候選報告](../reports/stage4/rank_regularization.json)，不根據本輪結果追加配對設定。

本輪完成 32 次新訓練。101 欄的 k＝10／40 都讓七、九月 TP 高於目前 k＝20，卻都未恢復舊 L2＝10 的七月成績；83 欄沒有同樣改善。全 75 候選按既定歷史規則，在十二月選到新 101 欄 k＝10，使主方案的最差歷史召回 19.17% → 19.63%，但三個開發月合計 TP 418 → 413、召回 25.46% → 25.15%。結果見[實驗報告](../reports/stage4/rank_pair_focus.json)與[路線診斷](../reports/stage4/rank_pair_focus_diagnostics.json)。

## 本輪只改什麼

[XGBoost 官方參數文件](https://xgboost.readthedocs.io/en/stable/parameter.html)說明，在 `lambdarank_pair_method=topk` 下，`lambdarank_num_pair_per_sample` 控制訓練配對所關注的固定前 k 個位置。本輪 k 是一個固定整數，**不是每天依訂單量重新計算的 10% 訓練切點**；每日提醒仍另外執行完整批次 10% 上限。

| 特徵包 | k＝10，新訓練 | k＝20，重播既有 L2＝100 模型 | k＝40，新訓練 |
| --- | --- | --- | --- |
| 地理／負載交互，共 83 欄 | `xgboost_rank_geo_l2_100_topk_10` | `xgboost_rank_geo_l2_100` | `xgboost_rank_geo_l2_100_topk_40` |
| 加 7＋14 天逾期堆積，共 101 欄 | `xgboost_rank_backlog_7_14d_l2_100_topk_10` | `xgboost_rank_backlog_7_14d_l2_100` | `xgboost_rank_backlog_7_14d_l2_100_topk_40` |

新增四個候選，各八個月份，共 32 次新 fit，均無 fit warnings；k＝20 的兩個排序候選及兩個同特徵分類候選，各重播八個月份，共 32 份既有模型。分類只提供背景對照，不與排序同時改參數。

固定設定包括：

- 原特徵 CSV 與 83／101 欄白名單；不新增、重算或篩選特徵。補值與類別編碼只使用成熟訓練資料 fit。
- 同一批成熟訓練 ID，依 `prediction_time`、`order_id` 遞增穩定排序；以核准日分組。保留全準時與全延遲日期，這些 query 沒有異類配對。
- L2＝100、400 棵樹、學習率 0.05、深度 4、`min_child_weight=10`、行／欄取樣 0.8、`hist`、seed 42；fit 兩執行緒、評分一執行緒。
- `rank:ndcg`、`lambdarank_pair_method=topk`、`ndcg_exp_gain=False`。除原生 `lambdarank_num_pair_per_sample` 外，wrapper 與原生 ranker 的其他參數不變。
- `eval_metric=ndcg@20` 保持不變，沒有 `eval_set`、early stopping、外部權重或續訓，因此該評估參數不驅動模型擬合或選模。
- margin 經嚴格單調 sigmoid 接到既有有界分數介面，沒有重新做機率校準；分數不能解讀成延遲機率。若不同 margin 被壓成同分，程式拒絕輸出。
