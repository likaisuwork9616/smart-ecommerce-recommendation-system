# Stage 4：逾期未送達訂單的 7／14 天堆積變化

本輪完成 72 次新月份訓練，固定每日完整批次 10% 提醒上限。主方案合併開發召回 **25.40% → 25.46%**，抓到延遲 **417 → 418**（差 +1）；仍未達三個 fold 各歷史月 30% 下限。結果來自[正式報告](../reports/stage4/backlog_changes.json)、[成對診斷](../reports/stage4/backlog_diagnostics.json)與[事前規格](../reports/stage4/backlog_changes_specification.json)。前輪為[路線與近期核准量實驗](STAGE4_ROUTE_LOAD_INTERACTIONS.md)。

十二月、二月、四月都已反覆用於開發；事前固定本輪規格不會使這些月份變成新的獨立測試。未重新評分原 2018-05-26 起保留期間，也未自動替換預設 Random Forest。

## 時點與特徵規格

對每筆核准時間 t，分別重建 t、t−7 天與 t−14 天的逾期未送達件數 B(s)。每個快照 s 都滿足：

- 核准時間在 `[s−90天,s)`；下界包含，s 當下及同時核准排除。
- 原承諾日期午夜加一天 `<=s`；缺承諾日期不能判定逾期。
- 送達日期缺值或 `>=s`；只有嚴格早於 s 的配送才移除，不能用當下已知的最終送達狀態回填過去。

原始負載母體為有效 purchase／approval 且 approval≥purchase 的所有訂單，包含取消、未完成與沒有延遲標籤的訂單。沿用原始承諾與主賣家定義；主賣家按最高品項價格、同價按最小 item sequence 決定。新增計數不讀 final status 或 delayed 標記。

群組為全域、主賣家、主賣家州→顧客州路線。每個群組、每個 lag 分別新增：

| 欄位 | 公式 |
| --- | --- |
| 過去堆積量 | B(t−lag) |
| 件數變化 | B(t)−B(t−lag) |
| 對數成長 | log1p(B(t))−log1p(B(t−lag)) |

當下 B(t) 已存在於基底的 `*_pending_overdue_90d`，本輪另以事件區間重算並逐筆確認相符。7 天與 14 天各增加 9 個數值，合併增加 18 個；沒有再加路線承諾類別、核准量趨勢、出貨期限或新的 C 搜尋。已知群組無件數時為 0；未知賣家／路線不合併，新增值保留缺值，無效查詢時間也保留缺值。

| 基底 | 原欄數 | 7 天 | 14 天 | 合併 |
| --- | --- | --- | --- | --- |
| Logistic 負載 C=1／0.01 | 65 | 74 | 74 | 83 |
| XGBoost 地理 | 83 | 92 | 92 | 101 |

上表為編碼前欄數。三個基底、三種 lag 組合，共九個固定候選；2017-07、08、09、10、11、12、2018-02、04 八月份各自重訓，共 72 個新版本。前輪 56 候選、448 版本只重載驗證，不重新 fit；完整比較共 65 候選、520 版本。

90 天視窗在每個快照各自移動，過期離窗也會造成負變化；下降不能直接解釋為配送改善。資料沒有取消時間，取消單可能在視窗內繼續被算作待件；也缺乏事件入庫與承諾修訂時間，沿用原承諾、州別、品項及配送記錄及時可得的假設。這是可觀測的負載代理，不能當成承運商真實容量或堵塞原因。

## 訓練、選模與提醒

新候選沿用各自原基底的參數、種子42、月初訓練訂單與排序。Logistic 保持 L2／lbfgs、C=1 或0.01、max_iter=10000，未收斂即停止。補值、缺值指標、Logistic標準化、類別補值與 OHE min_frequency20 都只 fit 訓練列。本輪 fit 使用2 workers，預測使用1 worker。

訓練沿用 deadline_wait0：核准與 training_outcome_known_time 都嚴格早於月初；訓練答案時間為實際配送與承諾日結束兩者較早者。歷史驗證仍只採選模 cutoff 前實際已送達結果，不把未知結果標成準時。選模依三個歷史月最低召回、合計TP、AP、固定候選順序；30% 只作適用判定。

每個完整核准日使用 floor(0.10×N) 個提醒，沒有跨日餘額；先讓未知結果參與排名占名額，再以已知結果計算指標。排序為分數降冪、order ID升冪。輸出分數未新增校準，不代表可靠延遲機率。

## 重現與推論

需要前輪留下的本機特徵、逐筆分數、原始CSV與月份模型；GitHub不含這些檔案，需先按前輪流程建立。來源或版本雜湊不符即停止，不用新訓練悄悄取代舊基準。

```powershell
.\.venv\Scripts\python.exe scripts\train_backlog_changes.py --specification-only --n-jobs 2
.\.venv\Scripts\python.exe scripts\train_backlog_changes.py --n-jobs 2
.\.venv\Scripts\python.exe scripts\diagnose_backlog_changes.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

規格在fit前儲存，正式執行後與事前快照一致；舊分數先建立索引再逐欄精確核對，避免重複整表掃描。新特徵／分數在 `data/processed/olist_delay_backlog_*.csv`，72個新版本在 `models/research/backlog_versions/`，選出的研究artifact為 `models/research/olist_delay_backlog_YYYY-MM.joblib`，全部由Git忽略。預設模型維持原版。

完整四月研究批次範例，依artifact白名單讀入類別、保留ZIP前導零，不含答案欄位：

```powershell
@'
from pathlib import Path
import joblib
import pandas as pd
artifact = joblib.load('models/research/olist_delay_backlog_2018-04.joblib')
features = pd.read_csv('data/processed/olist_delay_backlog_features.csv',
    float_precision='round_trip', dtype={c: object for c in artifact['categorical_features']})
month = pd.to_datetime(features.prediction_time).dt.strftime('%Y-%m')
columns = ['order_id', 'prediction_time'] + artifact['feature_names']
Path('.runtime/verification').mkdir(parents=True, exist_ok=True)
features.loc[month.eq('2018-04'), columns].to_csv('.runtime/verification/backlog_april_batch.csv', index=False)
'@ | .\.venv\Scripts\python.exe -
.\.venv\Scripts\python.exe scripts\predict_delay.py --model models\research\olist_delay_backlog_2018-04.joblib --features-csv .runtime\verification\backlog_april_batch.csv --complete-daily-batches --output .runtime\verification\backlog_april_predictions.csv
```
