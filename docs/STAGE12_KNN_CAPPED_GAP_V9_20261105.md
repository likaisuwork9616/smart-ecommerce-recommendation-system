高鄰居格的 7 個排除身分都來自早期 64 筆。該格每筆只選相似度排序前 500 名。結構上界取全部合格鄰居中會員列數最多的 500 個加總，選出的鄰居可能有較少的會員列。低鄰居格所有合格鄰居都入選，因此可以逐筆要求實際會員列數等於結構上界。盤點階段新增選樣、排名均為 0 筆。[完整盤點、來源指紋與剩餘格排名](../reports/stage12/retailrocket_session_knn_v9_gap_inventory_20261105.json)

## 事前補樣規格

兩格各取 **4 個新查詢**。採用相同配額，讓兩種工作量都有四筆個別計時，並能和上一輪採相同口徑的細層比較。每格四筆對稀有慢查詢的代表性仍有限。

1. 鎖定盤點收據與原始名冊 SHA。從候選中排除四組歷史名單的 152 個身分。只用結構欄位、固定細層及歷史身分選樣，推薦分數、target 與計時均不參與挑選。
2. 各格依 `SHA256(b"k1-gap-v9-20261105\x00" + bytes.fromhex(key_sha256))` 的 digest 位元組由小到大取前四名，平手依原 ordinal。兩格合併後按原 ordinal 排序。獨立完整排序必須得到相同八筆，封存名單後才讀七路原始列。名冊、來源或配額不符就停止。
3. 使用既有唯讀模型、V4 精確排名與 V6 計時器，在兩個全新保存目錄核對同樣八筆。高鄰居格須驗完整鄰居池 SHA、選中 500 位鄰居、切點平手、每位入選鄰居的會員列數，並檢查「實際投票列數 ≤ 結構上界」。低鄰居格須逐筆驗入選數等於合格鄰居數、實際投票列數等於結構上界。兩格都對回四臂原輸出、精確指標與資料來源。
4. 兩次共用 1,800 秒絕對期限、8 GiB RSS／20 GiB 新目錄上限、可用記憶體 4 GiB／磁碟 8 GiB 下限。發布前逐列比對兩份 ledger bytes、數量、串接 SHA 與 checkpoint 鏈；要求初末來源一致、外部觀察退出 0，並在退出後重新核算成本及覆蓋。

實測規劃 7–12 分鐘。若 8 筆全數通過，有樣本細層才可由 38／55 記為 40／55，所屬細層無樣本的母體由 5,615 降至 2,189 筆，歷史不同已驗查詢增至 160 筆。此規格階段新增選樣與重算均為 0 筆。[固定配額與執行條件](../reports/stage12/retailrocket_session_knn_v9_gap_sampling_specification_20261105.json)
