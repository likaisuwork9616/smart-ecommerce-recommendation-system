# Stage 6：第二個時間快照與跨期資料盤點

2026-10-27 完成現有本機資料盤點。**目前不能啟動可信的第二期 RFM 驗證**：找到的來源均為同一最終匯出；原 T=2018-09-01 之後只有 20 筆購買，19 筆取消、1 筆出貨中，依原事件資格沒有合格新增訂單。這是資料可用性結果，不是顧客沒有回購、模型失效或跨期穩定性成績。

正式數字見[聚合報告](../reports/stage6/rfm_temporal_data_inventory.json)，可重現入口為[盤點程式](../scripts/audit_rfm_temporal_data.py)，缺件與資料交接見[清單](templates/rfm_temporal_handoff/README.md)及[驗收紀錄範本](templates/rfm_temporal_handoff/acceptance_record.template.md)。本輪沒有建第二份個體 RFM、重估切點、執行分群／模型訓練或評估保留測試。

## 找到的來源與可支持範圍

檢查專案 `data/`、`.runtime/downloads/`、`.runtime/backups/` 與 Stage 4、5、RFM 三個預留交接目錄。這是指定專案路徑的盤點，不是全電腦、外接磁碟、雲端或供應端的全面搜尋。沒有查詢即時 MySQL 或重新查官方網站。

| 項目 | 實際查核 | 可支持什麼 |
| --- | --- | --- |
| 原始 Olist | 九份 CSV 的 hash 與既有來源一致；每張表僅發現 1 個不同內容版本 | 同一最終快照的回溯事件代理研究 |
| 下載與研究備份 | 下載 ZIP 有 9 份原表，v2／G3 備份各有 4 份原表；連原始檔共 26 個表副本，逐一 SHA-256 相同 | 備份恢復，不是新增的業務時間快照 |
| 本機匯入 | 來源 manifest 記錄 Kaggle 第 2 版；本機建置收據存在，本輪未重查資料庫 | 匯入／備份時間不能代表 2018 年事件首次可見時間 |
| 新資料交接 | 三個預留交接目錄都未建立；可接受的新增 as-of 快照為 0 | 跨期驗證維持 pending_data |
| 原 G3 | 69 份綁定來源 bytes 一致；未重跑 G3 核心 | 保留同快照結論，不增添跨期證據 |

沒有第二個 ZIP 並非唯一問題；如果能取得完整的版本事件流，也可以重建可信的兩期狀態。現有最終匯出可以切出不同日期的回溯代理視圖，但沒有原入庫／更正／狀態版本與完成水位，不能重建「當時已知」。原 T1 自身也是此限制下的回溯研究。

## 缺件與下一步

| 優先順序 | 仍缺什麼 | 完成後才能做什麼 |
| --- | --- | --- |
| 1 | 後期完整訂單、顧客、商品與付款資料；明確來源／版本／截止與控制總數 | 確認確實有可用第二期，而非同檔備份或尾端殘留事件 |
| 2 | 兩期可得／修訂時鐘、穩定顧客鍵、完成水位、補登／重開與金額對帳 | 驗收可比較母體與歷史 as-of；缺者只可保留回溯代理限制 |
| 3 | 驗收後固定 S2／T2、時區、完整母體與同 ID 交集、指標／門檻／曝光角色 | 才開始正式跨期設計；固定切點遷移與重新估切點分開報告 |
| 依用途 | 未來回購／價值的成熟結果窗口，或淨額／成本／行銷處置對照 | 才能談預測適用、LTV 或營運效果 |

建議先按[交接清單](templates/rfm_temporal_handoff/README.md)索取第 1、2 項並填[驗收紀錄](templates/rfm_temporal_handoff/acceptance_record.template.md)，不要現在執行 T2 分群。若原來源無法提供延伸資料，可另找有連續交易、穩定客戶鍵與可追溯版本的授權資料，另建研究；不同平台／不同匿名鍵不能直接當成同一顧客的第二快照。

原五種子 G3 通過及其 **25 個小組、1,791 位回購顧客支援不足**的限制維持。跨期的組大小尚未計算；G3 的 90% 一致率／0.80 ARI 是同快照抽樣門檻，不是跨期成功標準。Stage 4 仍固定每日 10% 提醒預算，Dashboard 仍暫緩。

## 驗證與重現

15 項合成測試通過，涵蓋左右截止、晚送達舊單、未成熟送達、取消／時鐘異常、缺核准的原代理語義、重複備份與未知完整性。實際耗時與日誌留在 `.runtime/verification/rfm-temporal-tests.json`／`.log`。另以 pandas 的欄位投影、向量時間遮罩與鍵連接獨立核對 83 項真實聚合，全數一致；紀錄位於 `.runtime/verification/rfm-temporal-independent.json`。這些是資料與程式核對，不是模型或跨期效果測試。

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_rfm_temporal_data -q
.\.venv\Scripts\python.exe scripts\audit_rfm_temporal_data.py --verify
```

`--verify` 重新只讀盤點並比對既有聚合，不寫檔或重跑 G2／G3；需要本機原九表、下載包、研究備份與來源收據。無參數只在報告不存在時建立首次聚合，既有檔不同則停止，後續新資料另開版本。公開 JSON 只含聚合、原始公開資料版本與程式來源；原始資料、備份及本機收據維持 Git 忽略。沒有重跑整個專案測試，也沒有把來源 bytes 核對稱為新一輪 G3 完整逐格驗收。

盤點與獨立核對完成後，使用者搬移執行資料至 `shop-mysql-runtime/` 並確認保留。為維持原始凍結路徑，`.runtime` 現為指向該實體目錄的 junction；兩處均受 Git 忽略。此搬移不產生新資料版本，沒有改寫 v2／G3 報告、guard 或來源程式。
