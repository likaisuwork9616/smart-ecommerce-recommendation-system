# Stage 4：單一完整研究核准日的離線交付驗收

本輪承接[模型卡與交付清單](STAGE4_MODEL_APPLICABILITY.md)，固定四設定與全部五種子，只讀既有分數驗收來源、日分母、排序、每日10%名額及輸出。沒有載入模型、重新預測、訓練、改選或新增效能結論；取消／結案與承諾版本方向維持[待資料](STAGE4_EVENT_SOURCE_AVAILABILITY.md)。

驗收範圍是**原凍結研究cohort的一個完整核准日**，不是生產系統的全量核准日或當時入庫完成證明。來源與交付契約見[本輪規格](../reports/stage4/daily_delivery_acceptance_specification.json)，實際聚合驗收見[正式結果](../reports/stage4/daily_delivery_acceptance.json)。

## 選日與日分母

先固定phase為`2018-02/2018-02/evaluation`，再從原凍結查詢名冊取**二月最早非空核准曆日**，選到2018-02-01。選日不用分數、答案、命中率或種子表現，沒有挑一個看起來較好的日子。

| 名冊對帳 | 實際範圍 |
| --- | ---: |
| 原138欄快取的pre-May研究查詢 | 70,844張 |
| 二月原研究cohort | 6,534張 |
| 2018-02-01原始核准單 | 245張 |
| 同日原研究eligible | 242張 |
| 同日被原規則排除 | 3張，最終status均為canceled；是事後cohort描述，不表示核准當下已知取消 |
| 研究cohort核准時間 | 01:29:49至23:51:37，沿原naive datetime，沒有推定或轉換業務時區 |
| 每設定／種子名額 | `floor(242×10%)＝24` |

獨立從原始orders重建原predicate：最終已送達、購買／核准／送達／承諾有效、核准≥購買、送達≥核准、承諾曆日≥核准曆日。先核對全70,844張ID與核准時間，再核對當日242張，而不是只相信一份標成「完整」的CSV。排除原因依序互斥記錄，不補零分、推定負標籤或把排除單臨時加入凍結分數。

日界為原研究時間的`2018-02-01 00:00≤approval<2018-02-02 00:00`。Olist沒有原入庫／日結完成訊號，因此即使名冊逐列對帳，也不能證明2018-02-02當時已收到所有訂單。

## 排序、旗標與未知答案

每組先核對當日全242張ID與精確核准時間、版本／種子唯一性及有限的`[0,1]`凍結排名分數，再按**分數降冪、order_id升冪**排列，名次1至242，前24列提醒。分數是未校準的排名分數，不解讀為個人延遲機率。不得先依路線、答案或高分子集縮小分母。

新名單逐列與原`predicted_delayed`旗標核對。原帳本沒有保存rank，因此不能聲稱「原rank逐欄重現」；本輪驗的是由凍結分數重新導出的排名、原提醒旗標，以及既有日邊界摘要。

evaluation的`known_at_selection`沿原契約全為False，表示該開發資料沒有作為歷史選模答案；**不是本日答案已知／未知的分母**。本輪不解析`outcome_for_metrics`，不算TP、FP、FN、召回、精確率或新路線表現。未知答案不應被提前排除的規則，另外以合成高分未知列與標籤改寫案例驗證，不能把合成測試說成當日實際未知答案的效果。

## 私有輸出與接手方式

| 本機Git忽略產物 | 內容 |
| --- | --- |
| `.runtime/offline_daily_delivery_2018-02-01/rankings.csv` | 4,840列，固定四設定→五種子→rank順序的完整排名 |
| 同目錄`alerts.csv` | 480列，精確等於完整排名的alert=True（邏輯1）子集；不是去重後的跨模型通知名單 |
| 同目錄`manifest.json` | 綁定來源、規格及私有CSV的SHA與列數，schema綁定本輪規格；只保留本機 |

兩份CSV固定九欄：

| 欄位 | 型別與含意 |
| --- | --- |
| version、seed | 固定四設定與五種子，對應本輪manifest的二月月版 |
| order_id、prediction_time | 原研究身分與核准時間，保留本機 |
| score | 凍結分數，CSV高精度寫出、round-trip解析後與來源精確比對 |
| rank | 每組完整1–242排列，非跨模型共用排名 |
| full_day_rows、daily_capacity | 242及24，不因答案或路線改變 |
| alert | boolean：True表示rank≤24，False表示未提醒，分別對應邏輯1／0 |

寫入前先檢查整個輸出bundle；有任一既存檔案內容不同就拒絕覆寫，不先改另一檔。路徑需解析後仍在專案`.runtime/`、受Git忽略且不碰來源。寫出後重新讀取，核對schema、全部逐筆分數／排名／旗標與alerts子集；只看列數或靠輸出自我排序不算驗證了分數來源。

公開JSON只交付來源／模型版本與聚合驗收，不提交訂單身分、ID hash、個體rank／score、cutoff分數或私有輸出digest。新電腦clone只取得程式與聚合證據；需另備本機原資料、凍結快取、帳本與對應模型bytes，不能宣稱僅clone就能重做全部驗收。

## 執行與停止條件

在專案根目錄使用既有`.venv`：

```powershell
.\.venv\Scripts\python.exe scripts\accept_frozen_daily_delivery.py --specification-only
.\.venv\Scripts\python.exe scripts\accept_frozen_daily_delivery.py
.\.venv\Scripts\python.exe -m unittest tests.test_delay_daily_delivery_acceptance tests.test_accept_frozen_daily_delivery -q
```

本輪規格是交付契約與來源快照，不是新模型訓練實驗。來源、20份月模型與程式SHA在驗收前後重查；既有規格、報告及本機輸出只接受相同內容重現。若日名冊、來源／版本、分數、旗標、輸出或忽略路徑不符就停止，不用「完整日」旗標跳過檢查。

本輪不啟動資料庫、呼叫API、載入模型、訓練或評分保留測試；也不建立自動通知。正式全量日結、資料取得時鐘、使用方處置與成本仍待驗收，模型適用要求仍依[模型卡](STAGE4_MODEL_APPLICABILITY.md)，Dashboard繼續暫緩。
