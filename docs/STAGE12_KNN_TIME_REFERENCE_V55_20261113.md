## 固定四例、八組參照

目標沿用 V54：V48 第 2／3 對投票累加、第 4／5 對正重疊，每例都保留序位 32／33 × R／C 四格，共 16 格。R＝V39 原版，C＝V46 候選。沒有只挑前輪較長的格，也不依本輪名次再篩選。

參照按兩分項 × 兩臂 × 兩序位分成八組，每組包含原六個正式 pair，共 48 個唯一 timer。原順序為第 1／3／5 對 CR、第 2／4／6 對 RC，保留每次的 pair、順序及該臂在對內先／後執行的標記。V47 與兩窗暖機只作來源核對，不放進時間分布；query 外層時間或尾端 commit 也不混入指定分項。

同群的兩個目標共用六值參照。這八組、16 格及其其他五值集合大量重疊，不能當作互相獨立的樣本，也不能跨臂、分項、序位或窗口混合。

## 統計口徑先固定

| 項目 | 定義 |
| --- | --- |
| 六值摘要 | 含目標自身，列最小、中位、最大、最大−最小與未縮放 MAD |
| 中位數 | 排序後偶數取中間兩值平均，奇數取中間值 |
| MAD | `median(abs(x − median(x)))`，不乘校正常數、不當異常門檻 |
| 名次 | 本群六次由長到短，1 為最長；精確同值保留占用的首／末名次，不以四捨五入或容差合併 |
| 計數 | 嚴格小於、等於、嚴格大於目標的個數；合計六，等於含自身 |
| 對中位數 | 目標−本組中位數，以及目標／中位數；中位數為零時倍數為 null |
| 其他五次 | 只排除當前 pair 的一格，再算自己的中位數、MAD、範圍、差與倍數；同群另一個 V54 目標保留 |
| 對五值範圍 | 嚴格低於、範圍內、嚴格高於；等於端點算範圍內 |

「高於其他五次最大值」等價於「本群六次唯一最大值」，不是額外獨立證據。其他五次仍是同一已曝光窗口的留一描述，不能當外部基準或保留驗證。六次中最長不等於統計顯著、異常、尖峰或候選造成。

輸入嚴格限定整數 pair 1–6 與非負有限數字，拒絕布林、缺漏、多餘、字串／浮點 pair key、非有限值及衍生溢位。摘要不修改輸入；中位數避免兩個大有限值相加溢位或極小值過早下溢。

### 四例如何解讀

第 2 對投票：R33 的 127.227 ms 在同組六次中唯一最長，高於六值中位數 77.316 ms，為其中位數 2.549 倍；其餘五次最高只有 53.658 ms。C33 同樣是自身組的最長，但只比其中位數多 8.299 ms（1.183 倍）。R32、C32 都排第 3、距各自中位數較近。兩臂的 33 都較長，程度不同，符合 V54 原版支持較大的描述。

第 3 對投票：R32、C32 都是各自六次最長，分別比中位數多 13.833／31.213 ms（1.271／1.453 倍）；R33 第 2、C33 第 5。V54 的候選臂內差距較大，同時對應 C32 位於本組上端與 C33 位於下端，不能只看其中一格。

第 4 對正重疊：C33 的 124.000 ms 為本組最長，較中位數多 36.734 ms（1.421 倍），其餘五次最高 95.102 ms；C32 則為本組最短，較中位數少 25.175 ms（0.720 倍）。原版 R33 也為本組最短，R32 第 4。候選同時出現兩端位置，與前輪 C33−C32 較大的差距一致。

第 5 對正重疊：R33 第 3 長，僅比中位數多 1.349 ms（1.015 倍）；R32 是最短，但只比中位數少 4.753 ms（0.932 倍）。C32 也在第 3、幾乎等於中位數（1.001 倍），C33 第 5、比中位數少 11.666 ms（0.866 倍）。這說明 V54 的原版臂內支持較大，並不等於 R33 在自身分布中特別高；不同序位本來就有不同時間水準，不能把其臂內差距直接當成異常。

## 來源與獨立重核

正式分析通過 V47–V54 前序結果唯讀重建、28 份原計時檔 bytes／SHA-256、1,344 筆身分／順序／工作量核對。從原紀錄取出的 48 個 timer 組成八組參照，其中 16 個目標絕對時間逐格精確等於 V54。

另以標準庫直接讀原紀錄、不使用 V55 計算函式，獨立核對八組與 16 格全部統計、名次、範圍關係、方法／來源綁定及 scope，共 937 個數值／結構與來源欄位通過；衍生浮點比較容差 1e−12，原始 timer 與 V54 採精確相等。正式報告產生後，`--audit` 唯讀重建完全相符。

## 判讀限制與下一步

本輪是已曝光 fixed48 validation 工程樣本的事後描述，不是未知資料成績。不能假定這六次是獨立同分布的負載實驗，原執行順序也不是負載校正。wall time 沒有分開 CPU、實體 I/O、排程等待或主機負載，因此仍不能歸因於 V46 解碼改動；維持暫不採用 V46 為完整入口預設。

下一步可繼續只用既有紀錄，查看同次執行的其他序位在同分項中是否也處於各自六次分布的上端或下端，區分差異只集中在少數查詢，或有較廣泛的共同方向。即使出現共同方向，也只能描述同次變動，仍不能證明主機負載或解碼因果。
