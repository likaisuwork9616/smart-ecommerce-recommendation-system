# Stage 12｜V66 B 實機時鐘能力校準計畫

依 [V62 規格](STAGE12_KNN_WALL_CPU_SPEC_V62_20261116.md)，在 [V65 A1–16 合成驗收](STAGE12_KNN_WALL_CPU_TYPED_V65_20261116.md)通過後，先固定 B 的流程、停止條件與時間預估。**本輪僅完成計畫，等待使用者確認後才實作及執行 B；沒有讀取本輪 clock metadata、跑新測試、試跑或校準。**C／D、原固定 48 筆、真實 model、SQL／query／training 及背景負載採樣均不在這次 B 的範圍。維持暫不採用 V46。

## 確認後的工作順序

目前有 V63 三讀工具及 V65 人工判定器，但**尚無 B 專用實機 collector**。V65 明確只接受 `origin=synthetic_fixture`；不能把實測資料改標籤後當成 B 通過，也不覆寫既有封存方法。

| 步驟 | 預定工作及提交點 |
| --- | --- |
| 1. 補齊收集器及真實來源接入 | 新增 B 專用入口，只能做一次 B；保留原三讀、原始整數與明確 provenance。新增假時鐘案例，涵蓋期限、樣本 cap、錯誤／取消、提前停止及不完整保存。先封存工具／案例／配置、更新 README、commit 並推送，才跑這批新案例 |
| 2. 驗收新收集路徑 | 執行已封存的假時鐘驗收，確認實測來源承接沒有改動 V62 判定算術；更新 README 並推送實際結果。失敗就停在修正與另版封存，不啟動實機 B |
| 3. 一次正式 B | 來源及封存核對通過後，在新 worker 的同一執行緒做下列固定流程；不額外預熱、試跑、重測或因結果追加 |
| 4. 保存及唯讀核對 | 保存原始資料／停止紀錄／聚合判定，獨立反讀公式、門檻、來源與檔案雜湊；更新 README，以繁體中文 commit 推上 main。即使 B 通過，也到此停止 |

使用者確認的是以上準備工作與**最多一次正式 B attempt**。若準備驗收不通過、正式 B 失敗或被取消，保留證據並回報；不自動再跑，也不啟動下一關。若未來實作需改 V62 門檻、增加 attempt 或延長時限，須另立計畫，不能在執行中調整。

## 一次正式 B 的量測流程

1. **事前來源核對**：確認 A 關收據、新 collector／案例與配置已封存且推送；建立 Git 忽略的私人執行目錄，記錄唯一 attempt。這一步不讀真實 model 或原固定 48 筆。
2. **啟動 B 計時與環境紀錄**：同一 worker／thread 記錄 Python、OS、程序／執行緒身分及來源 manifest；取得 `perf_counter`／`thread_time` 的 implementation、monotonic、adjustable、resolution 與可用性。兩鐘均須可用、monotonic 且不可調整。這些是確認後才會取得的本輪資料，現在沒有新值。
3. **三輪 dense 讀取**：每輪從首個 stamp 到末個 stamp 的 `w_before` 差達到 500,000,000 ns；每輪最多 1,000,000 組，包含初始 stamp。全部在同一執行緒，依序讀 `thread guard → wall_before → thread CPU → wall_after → thread guard`，三個時鐘值之間不插入驗證、配置或 I/O；讀完才核對及保存。
4. **十次 sleep 對照**：每次以同一三讀方式保存起訖，執行一次 `sleep(0.05)`。保存實際 wall／CPU，不用要求的 50 ms 代替實際 wall；不增加 C 的 `sleep(0.001)` 工作量。
5. **統計、判定及必要原始證據落盤**：每輪保存 CPU 零增量比例、正增量 count／min／p50／p95／max、wall 增量及 bracket 分布；另外保存全部 bracket、十次 sleep 實際值及比例。分位數用 nearest-rank，公式與門檻沿用 V62／V65 的精確算術。

**B 的 30 秒預算保守涵蓋：本輪環境／clock metadata 開始，到三輪讀取、sleep、當輪判定及必要原始證據落盤完成。**來源預檢、新工具開發／封存，以及之後的獨立反讀、公開文件與 Git 發布另記耗時。不能只把 30 秒當成讀取迴圈預算，將判定或必要落盤耗時移出去後宣稱 B 及時通過。

在可檢查的邊界與每次 sleep 前後檢查期限；若 OS 呼叫返回時已逾時，保存實際經過時間並判未確認。30 秒是成功的截止條件，**不是保證 OS 恰在第 30 秒返回**。逾時後只允許保存／整理失敗證據，不延長成功窗口；若 worker 被終止而無法保存部分 buffer，該部分明示缺失，不補造紀錄。

本次不啟用 profiler、額外暖機、200 ms collector、C 的 4,097 次探針／人工 workload，或 D 的 28 入口／56 前後校準。保持現有 GC、priority、affinity 與系統設定，不用清 cache 或調系統來換取通過。

## 門檻及停止條件

| 條件 | 固定處置 |
| --- | --- |
| 時鐘不可用、metadata 缺失／非 monotonic／可調整 | 不進入後續讀取，`clock_capability_unconfirmed` |
| 讀值倒退、跨執行緒、型別／欄位／來源結構不合 | 立即停止，`rejected_structure`；保留失敗點與已有原值 |
| 每輪達 1,000,000 組但 wall 尚未達 0.5 秒 | 停止，`clock_capability_unconfirmed`。若同一個末 stamp 同時達到 cap 與 0.5 秒，該輪可以完成，仍須通過其餘條件 |
| 完整 0.5 秒輪次的正 CPU 增量少於 10 個 | 停止，`clock_capability_unconfirmed`；不能用後面輪次或更長時間補足該輪 |
| 宣告 CPU resolution 向上取整已 >100,000 ns | 可在 dense 讀取前確定不足，`cpu_resolution_insufficient` |
| 任一完整輪、且正增量數足夠時，其正 CPU 增量 p95 >100,000 ns | 停止後續，`cpu_resolution_insufficient`；不憑第一筆大跳或尚未完成的 running p95 提早挑停 |
| 任一 bracket >100,000 ns | 此 max 門檻已無法恢復，可立即停止，`clock_capability_unconfirmed` |
| 完整固定集合的 bracket p99 >50,000 ns | `clock_capability_unconfirmed`；不以某輪暫時 p99 取代全部集合 |
| 任一次 sleep 實際 wall <40,000,000 ns | 已確定不符合單次要求，停止並記未確認；原始值保留 |
| 十次 sleep 的 CPU／wall 比例 p90 >0.10 | `clock_capability_unconfirmed`；不憑一筆高比例改規則或挑掉該次 |
| 整關逾 30 秒、取消、收集／保存失敗、必要資料未完成 | 停止，保留 `completed=false`、位置與原因；不能發布 B 通過 |

完整成功還須滿足：

`q = max(ceil(宣告 CPU resolution × 1e9), 三輪正 CPU 增量各自的 p95) ≤100,000 ns`。

完整三輪及十次 sleep 的固定槽位都保留；提前停止後未執行部分為 null／incomplete，不補零、不縮小成功分母、不丟慢值，也不追加 attempt。每個狀態保留全部失敗原因，不能因為某個單項符合而遮住其他失敗。

q 是本輪觀測到的 CPU 推進量篩檢，不是硬體真正解析度或誤差上界。CPU 零增量不代表沒有運算；不改用 process CPU、cycle counter 或平均多次 32／33 來宣稱達標，也不扣除估算探針成本。本輪不涉及 V39／V46 效能比較或等待歸因。

## 保存、驗證與目前進度

原始整數 stamp、原 clock metadata、身分、來源 hash、起訖／停止位置、三輪與十次 sleep 的完整或缺失狀態，保存於 Git 忽略目錄。公開收據只留方法／來源／證據描述、各輪統計、所有失敗原因與判定；實際刻度及能力只有未來執行後才能填寫，現在維持 null。新工具需明確保存真實來源標記，與 V65 合成 receipt 分開。

新 collector 的假時鐘驗收至少固定：三讀順序、0.5 秒與 cap 同點邊界、30 秒前／同點／逾時、跨執行緒／倒退／讀取例外、取消、停止後不再新增校準 stamp／thread CPU 樣本或 sleep、未執行槽位與失敗保存、真實來源不能偽裝人工來源。必要截止／收尾用 wall 讀取另列，不混入校準分布；若收尾時鐘也失敗，保留原錯誤與缺值。實作與案例須先封存推送，實際執行後再回報測試數，現在不預稱通過。
