# Stage 4：主賣家交運事件數單欄消融，101／102／104 欄比較

前輪[交運稀疏與交集診斷](STAGE4_HANDOVER_SPARSE_DIAGNOSTICS.md)發現，四月 104 欄模型新增漏掉的三張稀疏歷史訂單，與長承諾 SP→RJ 的兩張新增漏報屬不同群組。這輪保留核准時點、L2＝100、`topk10`、訓練答案時鐘及每日 10% 預算，只訓練「原 101 欄加交運事件數」的 102 欄模型，與既有 101／104 欄比較。

本輪的問題是：交運事件數本身是否有幫助，而在事件數之外再加入 p50／p90，會帶來哪些月份及路線得失。這是三個模型各自重新學習後的白名單比較，不能將它解釋為單一欄位對某張訂單的因果作用。

八次新訓練完成，102 欄的七月／九月 TP 與 104 欄相同，但八月、十一月與十二月更弱。三個開發月合計抓到 330 張延遲、召回 20.10%，比原 101 欄少 9 張、既有 104 欄少 7 張。三候選歷史選模及完整 78 候選主方案均未採用 102 欄；研究主方案維持 TP 413、召回 25.15%。

方法綁定[訓練前規格](../reports/stage4/handover_count_specification.json)，SHA-256 為 `297ebac7376a2590ffa6127f683953ea0575c4abe9b1ad672e3a29dbad173593`；數字來自[實驗報告](../reports/stage4/handover_count.json)及[診斷報告](../reports/stage4/handover_count_diagnostics.json)。這些月份已反覆用來發現問題及設計下一輪；事前固定本輪規格不會使它們變成未知資料測試。

沿用 Git 忽略的 `data/processed/olist_delay_handover_features.csv`：70,844 個核准嚴格早於 2018-05-01 的查詢點、137 個快取欄位，不重建或改寫。137 包含目標與診斷欄，並非模型輸入數；三個候選依自己的白名單取 101／102／104 欄。沒有替原保留期間建立新特徵或評分。

## 事件數的核准時點契約

`seller_handover_count_90d` 沿用 104 欄既有正式特徵值，定義為同主賣家、有效交運時間落在每筆核准查詢 `[t−90天,t)` 的其他訂單數，包含恰好 t−90 天，排除恰好 t、未來及本單事件。主賣家沿用最高單筆品項價格、同價取較小 `order_item_id` 的靜態映射；每張訂單只提供一個訂單層級交運代理事件。

有效事件要求 `購買 ≤ 核准 ≤ 交運`。缺送達時間可保留，不要求最終送達、不讀最終狀態或答案篩選；另隔離送達早於交運的矛盾。若該交運可以進入查詢，交運已早於 t，矛盾送達也必然早於 t，因此不會用未來送達提前刪除歷史事件。

**102 欄保留 0 筆及 1–4 筆的事件數，不套用五筆最低門檻。** 五筆規則只決定 104 欄的耗時分位是否可計算；本輪按 0／1–4／至少 5 筆分組是診斷，不會丟棄稀疏列、另建預算或另選模型。缺主賣家不合併成不明賣家群組，事件數為 0；無效查詢時間留缺失。

Olist 沒有逐品項交運、取消時間、事件入庫延遲或主檔版本。這是代表主賣家關聯訂單的歷史代理，不是每個包裹的真實物流速度。假設事件及時入庫、主檔可用與原承諾未改版仍保留；尚未交運的慢件不會貢獻交運事件，本輪不混入新的未交運負載特徵。

## 訓練、完整日預算與選模

八個月份版本為 2017-07、08、09、10、11、12、2018-02、04。訓練列、順序及核准日 query 與既有對照相同；`deadline_wait0` 要求核准與 `min(實際送達時間, 原承諾日次日午夜)` 均嚴格早於模型月初。按核准時間、ID 遞增穩定排序，保留全準時或全延遲的日群組；排序訓練的整數 10 不是動態每日 10%。

| 開發月 E | 歷史驗證月份 | 歷史答案成熟條件 |
| --- | --- | --- |
| 2017-12 | 2017-07、08、09 | 實際送達 `< 2017-12-01` |
| 2018-02 | 2017-09、10、11 | 實際送達 `< 2018-02-01` |
| 2018-04 | 2017-10、11、12 | 實際送達 `< 2018-04-01` |

各歷史月用自己的當月模型預測，不用較晚模型回頭評訓練列。分數為嚴格單調的 `sigmoid(raw margin)`，屬未校準排序分數。完整、已結束的每日批次按分數遞減、ID 遞增，取 `floor(0.10×N)`；每天獨立取整、不跨日借額。答案未知的訂單仍先參與整日排序，之後才遮蔽未知標籤計算歷史指標。核准時凍結特徵與日結提醒之間，最多仍有一天等待。

本輪八次新 fit、16 份既有 101／104 月份模型重播。原 77 候選的指標逐值凍結，再加入一個新候選，共 78 個；其餘 75 個舊候選的 600 份月份版本不重新評分。固定 101／102／104 的結果、三候選組按歷史選模的結果，與完整主方案分開列示。

選模沿用「三個已知答案歷史月最低召回最大 → 歷史合計 TP → 原始 AP → 固定候選順序」。30% 是適用程度的診斷要求，不是候選淘汰條件；不根據開發最高分或四月特定分組覆寫選模。七月／九月及十二月的已知對照、原三張及兩張漏報恢復情況都只供診斷。
