# Stage 4：每日10%、五種子下的模型適用範圍與交付清單

目前可交付的是**離線研究證據、模型卡與操作契約**，尚未證明可用於正式延遲提醒。原要求為各歷史驗證月至少30%召回；研究主方案與四組固定模型的五種子均未全面達標。取消／非送達結案與承諾版本方向已[列為待資料](STAGE4_EVENT_SOURCE_AVAILABILITY.md)，沒有新來源就不啟動該方向的訓練。

本輪整理既有報告、程式與本機檔案SHA，沒有新增模型、特徵、訓練、分數重播、推論、選模或保留測試評分，也沒有將研究主方案替換預設模型。

## 使用範圍與每日批次契約

| 面向 | 已驗證範圍與使用邊界 |
| --- | --- |
| 任務 | 以訂單核准時凍結的特徵，排序可能晚於承諾日送達的訂單；沒有驗證提醒介入能減少實際延遲 |
| 日批次 | 每個完整核准日先按分數降冪、order_id升冪，取`floor(N×10%)`；不足10張時0名額，不借用其他日名額 |
| 未知答案 | 在研究定義的完整日cohort中，未知答案先競爭名額，再評估當時已知答案；不可先刪未知、先切路線或在各組另取10% |
| 提醒時間 | 每單特徵以核准時間截斷，但最終10%名單要等當日批次完整；不是已驗證的逐筆即時提醒。實務日界、晚到、日結完成訊號與SLA尚未建立 |
| 母體 | 目前模型訓練與延遲效能評估cohort為時間合理且最終已送達的Olist訂單；歷史待件上下文可含其他有效核准單。這不代表全部真實核准、取消或未送達訂單已被效能驗證 |
| 地域與時間 | 巴西Olist歷史資料；固定模型查詢／評分限2018-05-01前，三個開發月為2017-12、2018-02、2018-04；未證明可轉移到現今臺灣、其他平台或新業務 |
| 資料時鐘 | 研究按已記錄事件時間截斷；缺少原入庫時鐘、承諾／主檔歷史版本，仍依賴及時取得與匯出值有效的假設，不能稱為已驗收的生產as-of資料流 |
| 分數 | 排序／分類分數，不是已校準的個人延遲機率；不可直接比較不同月份模型的分數尺度或由分數推算介入收益 |
| 特徵契約 | 沿原訓練補值、缺失指示、類別編碼與白名單；缺值或新類別可被接受，不等於資料品質或新賣家／新路線冷啟表現已驗收。不同輪的102欄可能不同，不可互換 |

三個開發月的1,845個名額占18,833單的約9.80%，是逐日向下取整的實際結果；「每日10%上限」不表示整月恰好10%。訓練的`topk=10`是排序配對參數，與提醒名額公式是不同設定。

## 已知弱點與不能外推的結論

| 既有證據 | 限制與含意 |

路線是最高價品項主賣家州→顧客州，不是實際物流路徑。A指主賣家歷史未觀測交運待件時齡p90在`(24,72]`小時，不是本單核准後再等24–72小時才預測。以上皆為既有預定焦點，沒有新增切片搜尋。來源：[四模型共同漏報](STAGE4_FOUR_MODEL_BOUNDARY.md)、[固定條件](STAGE4_CONDITIONAL_MATURE_SIGNALS.md)、[代表性稽核](STAGE4_COMPLETED_HISTORY_REPRESENTATIVENESS.md)及[來源查核](STAGE4_EVENT_SOURCE_AVAILABILITY.md)。

相容的推論artifact需要`format_version=1`、特徵白名單、門檻與前處理契約；每日上限wrapper另需保存預算契約。現有三個主方案fold wrapper符合此類介面；例如當前版本路徑為`models/research/olist_delay_unobserved_handover_age_2017-12.joblib`，另有二月、四月版本。它們是歷史月份選定的離線研究產物，沒有自動替新月份選版或重訓。

四組五種子的160份原始月版缺少上述通用CLI所需完整欄位，不能直接將任一檔案傳給`--model`就稱為可用服務。它們可由對應研究流程讀取，並非已封裝的五種子推論／集成產品。

有每日上限的wrapper只能使用`--features-csv`與`--complete-daily-batches`，不能單張`--order-id`。完整日旗標只是呼叫端聲明，程式不能證明沒有漏單、日已封閉或資料及時取得；CSV仍須另驗訂單唯一、prediction_time、全部必要特徵及研究cohort。原始CSV到生產全量日批次的擷取、匿名映射、版本與入庫流程尚未建立。

本輪只執行以下安全介面檢查，沒有載入artifact或輸出新分數：

```powershell
.\.venv\Scripts\python.exe scripts\predict_delay.py --help
```

實際離線推論的完整參數見[原版操作](STAGE4_DELAY_PREDICTION.md)與[腳本導覽](../scripts/README.md)。不要為展示而整本執行Notebook04：即使`RUN_TRAINING=False`，缺原模型或metrics時仍可能自動呼叫訓練。

## 下一步建議與停止條件

**先做一次離線交付驗收，不再加模型或切分同三個開發月。** 固定既有版本，選一個已檢視、來源與日cohort可核對的完整核准日，保留四設定與全部五種子並列，不挑最佳種子；只讀凍結分數展示排序、`floor(N×10%)`名額、未知答案處理與輸出schema。若另展示混合主方案wrapper，分開標示其身分。公開只交付去身分聚合範例及操作清單；驗收目標是接手者能重現既有行為，不是取得新的效能結論，也不建立自動通知。

這項演練的完成條件是來源／版本／日分母明確、排序與名單對帳、必要欄位和例外情境說明完備；不增加種子、調門檻、重新選模或宣稱未知資料成績。若無法證明完整日或來源版本，就標明該缺口並停止，不用「已完整」旗標掩蓋。

若目標是實際通知，後續先由使用方確認日終批次是否可接受、提醒由誰處理、誤報／漏報成本及資料完成訊號，再決定產品化驗收。沒有新來源或使用方條件時，維持本研究交付版本與待資料狀態；Dashboard、服務部署與新增訓練繼續暫緩。
