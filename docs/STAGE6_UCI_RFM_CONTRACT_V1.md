# UCI Online Retail II 回溯 RFM 資料契約 v1

本版固定 UCI 的兩個年度窗口、資料處理與跨期評估方法。**研究用途是已檢視歷史資料的回溯描述與跨期比較**；不是 Olist 的第二快照、未知資料測試或營運時點驗證。正式規則為[機器可讀契約](contracts/uci_rfm_v1.json)，版本與來源固定於[凍結清單](../reports/stage6/uci_rfm_v1_specification.json)，實際檢查與測試結果見[驗收收據](../reports/stage6/uci_rfm_v1_contract_acceptance.json)。

本輪只制定規則、核對既有檔案雜湊與 JSON 證據，並執行合成契約測試。沒有重新解析真實交易列、建置 RFM、估真實切點或計算跨期成績；資料建置器尚未實作。前輪的 776,621 筆候選、5,875 個顧客鍵及探索窗口人數仍是[盤點結果](STAGE6_UCI_RETAIL_II_INTAKE.md)，不能直接當成本契約的正式分母。

## 1. 時間窗口、資料角色與禁止前視

| 快照 | 購買窗口 [S,T) | 長度 | 固定用途 |
| --- | --- | ---: | --- |
| T1 | [2009-12-01 00:00:00, 2010-12-01 00:00:00) | 365 天 | 主口徑的完整活躍顧客用來估參考切點 |
| T2 | [2010-12-01 00:00:00, 2011-12-01 00:00:00) | 365 天 | 套用 T1 切點，作回溯跨期比較 |

兩窗相接、不重疊，涵蓋相同年度月份組合，避免半年重疊造成的機械性一致，也排除不完整的 2011 年 12 月。這不能消除年度環境變化或保證全量完整。先前探查的 2011-06-01 截止不列入本版正式比較，不因後續結果再換日期。

歷史起點固定 2009-12-01。每個 T 的顧客名冊、發票衝突、去重及資格判定，**必須先將資料限定在歷史起點 ≤ InvoiceDate < T，再做分組**。T2 的歷史名冊可以含前一年顧客，但 R／F／M 只計自己的 [S,T) 窗口。S 當秒包含、T 當秒排除；日期保持原始無時區、整秒精度，不自行指定 UTC 或夏令時間。

例如同一發票在 T1 前有一個時間、T1 後又出現另一個時間：T1 只能看到前者；T2 才能依自己截止以前的資料判斷衝突。不得使用前輪全檔建立的 `invoice_headers`、`bad_invoices`、`unique_rows` 或 `coherent_candidates` 視圖直接當快照資格。既有 SQLite 只能作為已核對且雜湊綁定的原始解碼列來源，仍須重新按 T 處理。

2011-12-01 以後的尾段不進入任何快照，也不叫保留測試。全檔品質、月別金額及部分窗口支援已在前輪檢視；T2 的角色固定為回溯比較。缺少原入庫／修訂時鐘與完成水位，因此事件日期只是歷史可得性的代理。

## 2. 來源、顧客與逐列保存

來源固定官方 XLSX、兩個工作表及既有下載／獨立核對證據；檔案 SHA-256、實際欄名及解析版本由凍結清單綁定。原始 Excel 不修改。實際欄位為 Invoice、StockCode、Description、Quantity、InvoiceDate、Price、Customer ID、Country。

| 項目 | 固定規則 |
| --- | --- |
| 原始列識別 | 工作表名稱＋Excel 列號，保留來源及每個處理口徑的去向 |
| 顧客鍵 | 五位 ASCII 數字的原始 Customer ID；數值儲存格式按前輪標準化為文字，不猜前導零或重新編碼 |
| 顧客缺值 | 留在無法連接的明細／發票帳；不補值、不共用一個「未知顧客」，不以國家猜顧客 |
| 顧客母體 U(T) | 該 T 前任何原始列中出現的有效已知顧客鍵，包括只有取消、調整、免費或品質隔離列者；不先以消費或金額篩掉 |
| 同鍵跨年 | 假設為可追蹤代理鍵，尚無證據證明未重用、同一自然人或完整顧客註冊母體 |
| 非空但非法顧客鍵 | 停止建置，不默默轉成缺值 |
| 描述缺值 | 保留並標記，不用描述補價格、顧客或推斷商品資格 |
| 日期失效、含時區／小數秒、早於歷史起點 | 因無法可靠切窗或偏離原契約而停止建置；不能把錯誤列藏到某個時期外 |
| 原檔／表頭／工作表變更、公式、數值溢位 | 停止，保留失敗證據；來源不同需另立版本 |

U1 必須是 U2 的子集。T2 新出現的鍵稱「新增觀察鍵」，不稱真實新客；無合格購買或零活動不等於流失。

## 3. 重複列與四個固定口徑

完全相同的判定使用八欄解碼後值；數字格式標準化，空值與全空白字串視為缺值，其餘文字大小寫及非空白內容保留。不能按發票號或發票＋商品只留一列，多品項及同商品不同價格／數量仍保留。

**主去重規則：**每個八欄相同群只保留一列。代表列先依 `Year 2009-2010`、`Year 2010-2011` 的順序，再取最小 Excel 列號。此規則是研究假設；沒有明細唯一鍵，不能宣稱被排除的列都是真實錯誤。

**重複敏感度規則：**同一八欄群取「單一工作表出現次數的最大值」。選出該群列數最多的工作表，平手沿用上述表順序，保留該表內該群的全部列。這保留同表重複的可能交易量，同時避免把兩表重疊直接相加。例如 A 表 3 列、B 表 2 列，主口徑保留 1、敏感度保留 3，均不是 5。其真實交易量仍未知。

| 固定口徑 | 重複處理 | M 計入範圍 |
| --- | --- | --- |
| main（主口徑） | 八欄相同保留一列 | 所有合格正價明細代碼 |
| duplicate_sensitivity | 每群取單表最大出現次數 | 所有合格正價明細代碼 |
| code_sensitivity | 八欄相同保留一列 | 僅符合 `[0-9]{5}[A-Za-z]*` 的代碼 |
| combined_sensitivity | 每群取單表最大出現次數 | 僅符合上述代碼形狀 |

四個口徑全部預先保留，不按 T2 結果挑最佳版本。代碼篩選**只改 M，不改發票資格、R、F 或顧客名冊**；因此僅有費用代碼的活躍顧客，在代碼敏感度下 M 可以是 0。正規表示式只是代碼外形，並非可靠的商品分類字典。

每個原始前綴列都需有重複群、代表列與保留／多餘狀態映射；主排除原因與所有品質旗標分開保存。前輪跨表重疊及同表重複統計用來支持這項設計，不當成本版重算結果。

## 4. 發票時間衝突、取消、零價與異常數值

先以該 T 前同一發票的**全部列**檢查表頭，不能先刪負數或缺顧客列後才檢查。購買發票須符合六位 ASCII 數字；C 開頭不分大小寫一律屬取消文件。C 後綴不與原單號機械配對。

| 情況 | 固定處理 |
| --- | --- |
| 同購買發票有多時間、多已知顧客、混合缺顧客／已知顧客，或多國家（含缺值差異） | 整張發票品質隔離；不取最早／最晚、不按時間拆單 |
| 發票缺值 | 逐列品質隔離，不造發票號 |
| 全張顧客缺值 | 無法連接帳，保留原列與金額；不進顧客 RFM |
| 國家全張一致缺值 | 保留旗標，不推測國家；國家不作購買篩選 |
| 購買發票有缺商品代碼、無效／缺數量或價格、非整數／非正數量、負價格 | 整張購買發票品質隔離，避免只留好列而把部分金額當完整 |
| 正整數數量、零價格 | 免費列，保留但不構成付費活動；不因零價本身隔離整張發票 |
| C 開頭，無論數量正負 | 全部排除 R／F／M；保留取消帳與有號金額，包括前輪發現的正數取消列 |
| 非六位數、非 C 文件 | 調整文件帳，排除 R／F／M，不假定為購買 |
| 非 C 負數量 | 屬數值異常／調整；若是六位數購買發票則依整張品質隔離處理，不當退款配對 |
| 極端正數量／單價 | 不縮尾、不刪除；提供分布與極端值診斷 |

合格購買發票須表頭一致、顧客已知、無上述品質隔離，且至少有一列「商品代碼非空、正整數數量、正價格」的付費明細。免費列不增加 F；同張多個付費品項 F 仍只加 1。取消不回頭沖銷以前的購買，因此本版只研究正價明細毛額代理，不能解讀成最後成立／結算／淨銷售額。

品質隔離發票連接到該 T 前其所有已知顧客鍵；只要任一成員列在 [S,T)，相關顧客本窗標為有隔離。缺發票列只連自己的已知顧客。僅出現在 S 前的隔離保留歷史診斷，不遮罩本窗乾淨活動。完全缺顧客的交易不能映射到其他人的未知狀態，需另報其列數、發票及金額占比。

逐列主原因依序為：取消文件 → 其他調整文件 → 缺發票 → 表頭衝突 → 未知顧客 → 購買數值／商品代碼異常 → 重複多餘列 → 免費列 → 合格付費列。每列只有一個主原因，另外保留所有旗標；去重映射另行對帳，不能將可重疊異常統計直接相加。

## 5. R／F／M、精度與零活動

| 欄位 | 正式定義 |
| --- | --- |
| R_seconds | T 減本窗最後一張合格購買發票時間；精確整秒，活躍範圍 1～31,536,000 秒 |
| R_days | 僅展示時除以 86,400，取六位小數；計切點與比較用原整秒，不取整天 |
| F_invoices | [S,T) 的不同合格購買發票數，不是明細列數 |
| M_milli_GBP | 同一批合格發票、該口徑所選付費明細的數量×價格總和，整數單位 0.001 GBP |

以解碼後價格文字作 Decimal 解析，精確轉成每 GBP 1,000 單位再乘整數數量；不使用二進位浮點四捨五入、不換匯、不逐列取到分。最多三位小數；若多於三位則停止另立版本。逐列與加總均驗 signed int64 範圍；非可解析數值的原始有號金額保持未知，不能填 0。

主口徑名稱固定為**正價發票明細毛額代理，可能包含費用／調整**。非標準代碼不自動等同錯誤；主口徑仍計入其合格正價明細。它不是純商品毛額、淨營收、利潤或 LTV，沒有取消原單映射、成本或結算證據。

| 狀態 | 條件 | 正式 R／F／M | 數值評估 |
| --- | --- | --- | --- |
| active_complete | 本窗有合格發票且無本窗品質隔離 | 正常 R、正 F、該口徑 M | 可納入 |
| inactive_complete | 本窗無合格發票／隔離，但 T 前曾有合格發票 | null／0／0 | 不進活躍分位數；留在母體與狀態轉移 |
| observed_no_eligible_history | T 前有已知鍵，但從未觀察到合格發票，且本窗無隔離 | null／0／0 | 獨立列報，不叫流失或既有購買者 |
| active_with_quarantine | 本窗有部分合格發票，也有品質隔離 | 三欄皆 null | 不納入完整數值比較 |
| inactive_with_quarantine | 本窗沒有合格發票，但有品質隔離 | 三欄皆 null | 不當成乾淨零活動 |

先判品質隔離，再判本窗有無合格發票、再判歷史合格發票。隔離顧客的部分可知 R／F／M 放在獨立 `partial_*` 診斷欄，不混入正式數值。歷史僅從資料起點觀察，不聲稱完整終身記錄。

## 6. 固定評估方式

### 參考切點及後期套用

只用 **main／T1／active_complete** 顧客估 R_seconds、F、M 的 P20／40／60／80。參考完整活躍人數若少於 200，只報描述與狀態，不估切點，也不換窗口救結果。分位數用排序後第 `ceil(n×p)` 個值，無插值；描述的 P0／P100 分別取最小／最大。

切點排序去重，刪除等於參考最大值的切點，避免空的最高箱；相同值不按 ID 或亂數拆開。令 j 為嚴格小於觀察值的切點數、K 為切點數＋1：F／M 分數為 j＋1，R 分數為 K−j；值等於切點時留在較低數值箱。常數軸只有一級、分數 1，明標退化，不強迫五級。

將 main／T1 的切點單次保存後，原封套用 T2 及所有敏感度口徑。T2 超出 T1 範圍時自然落在最外箱，不改切點、不重估分位數、不挑表現較好的口徑。本輪僅以合成整數案例測試這個數學定義，未讀真實顧客值。

### 母體、配對與指標

| 層次 | 固定分母及報告 |
| --- | --- |
| 完整觀察母體 | 各 T 的 U、五狀態人數；U1 上的 5×5 狀態轉移；U2\U1 新增觀察鍵另列 |
| 各期完整活躍 | R／F／M 的最小、P25／50／75／95／99、最大；F≥2 比例，分母明列為該期完整活躍 |
| 同顧客數值配對 | 僅 U1 中兩期皆 active_complete；必報配對 n／U1、占各期活躍比例及被排除狀態 |
| 數值變化 | T2−T1 的上述分位數、絕對變化 P50／P90；Spearman 採同值平均秩 |
| 分級變化 | 每軸相同級／相差至多一級比例、joint tuple 完全一致率、各軸及 joint 轉移人數與 T1 列分母比例、tuple 分割 ARI |
| 清理敏感度 | 三個對照各與同 T 的 main 依同顧客配對；M 差值分位數、總差與 main 非零時的相對差、分級一致率及支援人數 |

四口徑的名冊、狀態、R 與 F 必須一致；本版敏感度只應影響 M 及其分級。若不一致先視為實作／契約問題，不選其中一組繼續。

配對少於 200 時不報 Spearman 或 ARI，保留描述與轉移帳並標支援不足；任一軸為常數時 Spearman 為 null，ARI 分母為零時亦為 null 並標退化。空分母不填 100%。ARI 衡量群組分割，不等同分數意義一致，因此須與 tuple 完全一致率並報。

跨期一致率不設定任意通過門檻；行為自然變化不等於模型失敗，也不沿用 Olist 的 G3 90% 或任何既有小組人數。這是固定方法下的描述，不提供母體信賴區間、因果或業務效果結論，也不進行新模型訓練或五種子選擇。

### 小組支援限制

每個 T、每個口徑，以該期 active_complete 人數 N 計 `max(50, ceil(0.01×N))`，同時檢查每軸箱與每個非空 joint tuple；0 人另標空箱。列出支援不足組數、涉及人數與最小組人數。這是事先設定的研究呈現限制，不是統計效力或行銷可用性的保證；不足時不合箱、不改切點救結果，也不對小組作業務成效主張。

## 7. 未來產物與建置驗收

本輪不建立真實資料集目錄。未來使用 `shop-mysql-runtime/uci_rfm_dataset_v1/<arm>/<T_id>/`，每組包含顧客表、發票判定表、逐列原因帳與重複映射；欄位、排序、null、布林及整數格式完整列於機器契約。公開報告只放聚合、來源 hashes、版本及驗收結果；個體顧客／發票與逐列資料維持 Git 忽略。

| 建置驗收條件 | 要證明什麼 |
| --- | --- |
| 原列與排除對帳 | 每個 T 前原列恰有一個主原因，所有列與重複映射可回追；原始檔不變 |
| 顧客完整性 | 任何已知前綴鍵均保留一列，U1⊆U2，四口徑母體與狀態一致 |
| R／F／M 對帳 | 每個口徑整數金額從列→發票→顧客一致，零活動與 null 隔離不混淆；R／F 跨口徑相同 |
| 防前視合成測試 | 在 T1 後追加同發票不同時間／顧客／價格／國家，不得改變 T1；S 包含、T 排除且後期 ID 不進前期名冊 |
| 獨立核算 | 另一路徑完整重算顧客值、發票／逐列決策與去重映射，不僅比較 hashes 或總額 |
| 寫入與反讀 | 整包事前防覆寫、單次建置、完整反讀，最後才寫外部 guard；部分失敗保留證據，禁止刪檔重播 |

先完成建置與獨立對帳，才能估 T1 真實切點並開始跨期報告。未達建置驗收不報分級成績；若來源或規則要改，使用新版本與新目錄，保留 v1 及既有檢視紀錄。
