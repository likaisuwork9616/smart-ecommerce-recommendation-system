# Stage 12：高於 1,945 位鄰居的尾端補樣

本輪補強 `1101/n5/v4` 中 eligible_neighbors > 1,945 的區段，沿用原 V6、已在 V18 重測的同一筆 n5 對照，同步記錄系統負載。這是已曝光 validation 的工程成本驗算，完整 validation 驗收與保留測試仍未啟動。

## 尾端母體與歷史排除

完整核對 166,897 筆結構名冊與 55 格覆蓋。V18 的 8 個新身分加入後，共有 **226 個歷史身分、164 個可比較查詢**；V18 的兩筆舊對照沒有重複計數。`1101/n5/v4` 全格 4,221 筆，歷史排除 7 筆，可選 4,214 筆；其中既有 5 個可比較查詢都在 1,945 位鄰居以下或等於門檻。

尾端 **888 筆**中，排除一筆 V3 歷史身分後可選 **887 筆**，目前沒有具有相同分項計時口徑的尾端樣本。三段容量如下；投票結構欄是上界，不能代替實際 SQL 取列量。

| 鄰居數區段 | 母體 | 歷史排除 | 可選 | 可選最大鄰居數 |
| --- | ---: | ---: | ---: | ---: |
| 1,946–2,499 | 593 | 0 | 593 | 2,499 |
| 2,500–2,999 | 202 | 1 | 201 | 2,992 |
| 3,000–4,999 | 93 | 0 | 93 | 4,071 |

三段最大鄰居數各只有一筆，均未被歷史排除；最高為 **4,071 位**。固定對照有 **1,945 位鄰居**，已核對與 V6、V18 的完整科學 payload 一致；它不屬於新尾端樣本。

盤點前後核對 **404 份來源**，每次 **111,503,964 bytes**；另核對 V18 三份帳本共 30 列與原 V6 48 列。沒有重讀大型模型或原始資料，新增選樣與排名均為 0。

下一步封存三段各兩筆新樣本：一筆結構最大者加一筆固定雜湊樣本，再加原固定對照。同批循序三輪並保留負載觀測。刻意補尾的樣本不作整格或 55 格母體工時估計。[盤點收據](../reports/stage12/retailrocket_session_knn_v19_tail_inventory_20261106.json)

## 三段固定補樣規格

三段 `1,946–2,499`、`2,500–2,999`、`3,000–4,999` 各選 **2 筆新查詢**，共 6 筆；再沿用原 V6、V18 的同一筆 n5 對照，共 **7 筆**。新樣本全部排除 226 個歷史身分。

各段先選未驗候選中 **eligible_neighbors 最大**的一筆；若最大值同分，以固定前綴 `k1-tail-v19-20261106` 加 NUL 與身分 SHA 原始 bytes 計算雜湊，依雜湊與原 ordinal 排序破同分。第二筆從剩餘候選取該雜湊最小者，確保不與最大值樣本重複。新樣本分別標記 `segment_max`、`hash`，原對照標記 `anchor`。

這個選法會納入三段可選上緣 **2,499／2,992／4,071 位鄰居**的案例。選樣只讀結構與歷史身分，不使用標籤、預測或計時；任一段不足兩筆或來源／容量不符即停止，不移轉配額、不換種子、不遞補。另一套字面邊界分類與完整排序獨立核對名單；封存後才讀七路排名輸入。

七筆按原 ordinal 混合排序，同一批及同一順序 **循序重測 3 輪，共 21 次工程核對**。每輪使用新唯讀連線及 checkpoint，保留所有輪次；不剔除暖機、不依耗時追加重跑。三份帳本須逐位元組相同，對照須對回原 V6 的完整科學 payload。排名與分項計時沿用原 V4／V6，未採用前輪失敗的 SQL 候選。

## 負載觀測、計時與解讀限制

沿用 V18 的背景觀測器，目標每 **200ms** 取得全系統 CPU、記憶體、可讀取的磁碟累積量，以及工作程序與名稱以 `ollama` 開頭的程序 CPU／RSS。私人紀錄保留 PID 與建立時間避免錯接重啟程序；公開只呈現聚合數字。首筆 CPU 不納入摘要，缺失值不補零；每輪至少兩個有效 CPU 區間與有效記憶體紀錄，首尾涵蓋完整驗證入口，三輪觀測及驗證不可重疊。

分列驗證入口時間、首尾觀測區間與採集耗時；系統 CPU 按實際區間加權，並記錄排程造成的長間隔。觀測器有開銷，不能把採集時間再次加進查詢成本。負載只支持整輪描述，不足以歸因到短查詢、SQL 或 Ollama；未量測其他名稱 runner、GPU 或 token 生成速度。來源雜湊與七路資料抽取不在每輪負載觀測範圍內。

成本先於每筆每輪計算 verify＋append（扣內含 commit 與直接預算保存），再統計同一查詢三輪的最小／中位／最大值與變幅。rank／vote 內含於 verify；setup、尾端與整批 commit 另列，避免重複相加。六筆新樣本、舊對照、三個尾段與最大值／雜湊選法分開描述；不同窗口的對照成本不視為優化加速。

因每段配額相同且刻意保留最大鄰居數，樣本不是整格或尾端母體的均勻抽樣。**不發布尾端、整格或全部 55 格的人口加權工時估計**，也不把這七筆的合併平均當成整格平均成本。
