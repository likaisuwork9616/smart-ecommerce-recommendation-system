## 是否可以另開研究、下一步怎麼做

| 項目 | 判斷 | 下一步 |
| --- | --- | --- |
| 獨立 UCI 回溯 RFM | 有條件可行 | 有顧客鍵、發票、日期、數量、價格與兩年以上事件支援，先寫獨立資料契約 |
| 去重與發票資格 | 待定案 | 保留原始帳、去重映射及排除帳；明訂跨表優先順序、同表完全相同列敏感度、83 張時間衝突發票處理 |
| R／F／M 定義 | 待凍結 | R 的時鐘與單位、F 以不同合格發票而非明細列計數；M 先定義正購買金額及費用／調整範圍，不稱淨營收 |
| 缺值與取消 | 待凍結 | 未知顧客不補造 ID；取消獨立保留，沒有原單映射不自動沖銷；零價、負價及極端值另立政策 |
| 跨期設計 | 可起草、未執行 | 固定等長 [S,T)、歷史顧客母體、零活動／未知、共同顧客與新增觀察鍵分流；明列窗口重疊及季節性影響 |
| 評估角色 | 尚未凍結 | 已看過全檔品質、月別金額及上述支援；後續稱回溯／開發驗證，事先停止用後期結果反覆調規則；真正未知驗證需另取未檢視資料 |
| 歷史 as-of／營運完整性 | 不足 | 缺原可得／修訂時鐘、完成水位、原銷售取消關聯；本檔只支援事件時間代理的回溯研究 |
| Olist 接續與既有限制 | 仍待原交接資料 | UCI 不混接 Olist ID、不沿用 Olist 切點或跨期門檻；原 25 個小組限制保留 |

建議下一輪先完成「UCI 回溯 RFM 資料契約與清理敏感度規格」，再實作建置器並獨立對帳，之後才做描述、候選分級與跨期比較。各截止的資格應只使用該截止前的事件資料；不能把本輪用全檔找出的未來衝突資訊當成當時已知。Stage 4 仍固定每日 10% 提醒預算；Dashboard 繼續暫緩。
