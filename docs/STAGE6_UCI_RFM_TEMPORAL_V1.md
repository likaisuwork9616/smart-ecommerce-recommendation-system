# UCI RFM v1 固定切點、跨期比較與小組支援

本輪依[凍結契約](STAGE6_UCI_RFM_CONTRACT_V1.md)，在已驗收的[雙期資料集](STAGE6_UCI_RFM_BUILD_V1.md)上，**單次估 main／T1 切點，固定套用 T2 與三個敏感度口徑**。兩期各 365 天且不重疊：T1 [2009-12-01, 2010-12-01)、T2 [2010-12-01, 2011-12-01)。

結論是：四個清理口徑大多得到相同分級，但同顧客跨年的分級變化明顯；單軸箱有足夠人數，125 種聯合組合中仍有大量小組支援不足。契約沒有跨期一致率通過門檻，因此本輪只宣告**執行與獨立驗收通過**，不宣告「跨期穩定性通過」或營運可用。

## 單軸及聯合小組支援

門檻固定 `max(50, ceil(1%×當期完整活躍人數))`，本次八組皆為 **50 人**。各軸五個箱在八組資料中都達門檻；主口徑最小單軸箱 T1 為 510 人、T2 為 512 人。

| 口徑 | T1 不足組／非空組 | T1 涉及人數 | T2 不足組／非空組 | T2 涉及人數 |
| --- | ---: | ---: | ---: | ---: |
| main | 87／114 | 1,531 | 83／112 | 1,422 |
| duplicate_sensitivity | 84／113 | 1,423 | 83／112 | 1,422 |
| code_sensitivity | 87／115 | 1,484 | 82／112 | 1,368 |
| combined_sensitivity | 86／115 | 1,427 | 83／112 | 1,418 |

主口徑共有 125 種可能 tuple，T1 空組 11、非空 114；其中 87 組不足 50 人，涉及 1,531 人（36.1767%）。T2 空組 13、非空 112；其中 83 組不足，涉及 1,422 人（33.3099%）。兩期最小非空組都是 1 人。

小組不足限制完整保留，沒有為了改善支援而合箱、重估切點或挑口徑。這些 125 格不能整體當成可直接行銷的客群；單軸支援足夠也不是營運效果保證。

## 獨立驗收、保存與操作

主路徑以整數逆經驗分位數、二倍平均秩及 Fraction ARI 計算。獨立路徑用 pandas 重讀已驗收顧客 CSV、NumPy `inverted_cdf`／`searchsorted`、SciPy 平均同秩 Spearman 與 scikit-learn ARI，並另算狀態轉移、支援及原始窗口缺值金額。獨立重算參考切點只用於核對保存的同一組切點，不是第二個選模候選。

八份 scores.csv、panel.csv 共 46,914 筆／533,398 格全部反讀一致；JSON 核對 59,798 個欄值（包含獨立聚合核算與保存後反讀）。整數與計數精確相同，衍生浮點使用 absolute／relative 1e-12 容忍度。未定義相關／ARI／空分母均保持 null，沒有補成 100%。實際處理 23.615 秒，沒有重建既有 RFM 或訓練模型。

所有保存檔案在 `shop`：`shop-mysql-runtime/uci_rfm_temporal_v1/` 有單次 cutpoints.json、八份分級、panel、manifest 與 guard；測試及事前證據放 `shop-mysql-runtime/verification/uci-rfm-temporal-v1/`。這些逐筆與執行檔由 Git 忽略；公開報告只含聚合與來源 hashes。本輪使用 `.venv` 既有套件，沒有安裝新套件。

```powershell
# 現有完整產物：只核保存 bytes，不重估切點或重算指標。
.\.venv\Scripts\python.exe -B scripts\run_uci_rfm_temporal_v1.py --verify
```

只有首次空白命名空間才使用 `--prepare`、`--run`；完整既有產物只驗證，部分失敗保留並拒絕重播。原 v1 契約、前輪建置資料、Olist 及 Stage 4／5 證據均不改寫。
