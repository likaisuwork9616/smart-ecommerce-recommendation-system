# Stage 12｜V68 既有時鐘證據的能力限制與後續方案

本輪只整理 V67 已保存的紀錄與 V62／V66 事前規格，不新增量測、clock metadata、測試、C／D 或原固定 48 筆重跑，也不改寫 V67 的結果。**V67 的唯一 attempt 不符合既定 B 條件，正式狀態維持 `clock_capability_unconfirmed`。目前不能發布 1 ms 尺度的細項 wall／CPU 判讀；也不能據此斷言任何環境都永遠無法量測。**維持暫不採用 V46，保留測試 locked。

## 來源與本輪核對

主要依據為 [V67 正式結果](../reports/stage12/retailrocket_session_knn_v67_clock_result_20261116.json)、[V67 獨立 B 反讀](../reports/stage12/retailrocket_session_knn_v67_clock_independent_B_audit_20261116.json)、[V67 假驗收](../reports/stage12/retailrocket_session_knn_v67_clock_acceptance_r2_20261116.json)及其綁定的私人 raw／outcome／reservation／claim；門檻來自 [V62 規格](STAGE12_KNN_WALL_CPU_SPEC_V62_20261116.md)與 [V66 計畫](STAGE12_KNN_CLOCK_CALIBRATION_PLAN_V66_20261116.md)。

本輪唯讀重核164個唯一檔案描述的 bytes／SHA256，並從 raw 重算所需統計；V67原收據的163保持不變，本輪多核對其獨立反讀腳本描述。不 import 或執行 collector、runner、測試 suite。公開只留聚合數字、相對路徑及雜湊，原始絕對刻度、環境身分與逐組資料仍在 Git 忽略目錄。[本輪證據收據](../reports/stage12/retailrocket_session_knn_v68_clock_limits_evidence_20261116.json)。

## 已有的量測事實

下表全是 V67 舊紀錄或其唯讀算術，沒有本輪新實測值。

| 項目 | 既有結果 | 判讀範圍 |
| --- | --- | --- |
| 工具合成驗收 | 123 項通過，失敗／錯誤／跳過 0 | 指定假時鐘與人工案例的行為驗收；不是實機精度或開銷驗收 |
| 正式 attempt | 1 次，worker 正常退出，無 timeout | V67 一次性額度已用完；不能再用相同 reservation 補跑 |
| 完整收集量 | 完整輪 0／3；sleep 0／10 | 首輪 incomplete；後兩輪及十次 sleep 為 null，不能當零耗時或合格 |
| 首輪片段 | 30,570 組；首末 wall 差 301,961,900 ns（0.3019619 秒） | 未滿事前固定的 0.5 秒，即使正 CPU 增量有至少十個也不算完成輪 |
| 正式停止原因 | 最後一組 bracket 227,300 ns（0.2273 ms）>100,000 ns | 是這次 attempt 已確定不符的 max 條件；保留末點，不刪除後改判 |
| 片段 bracket | p50 1,000 ns、p95 1,100 ns、p99 2,600 ns；只有末點超過 max 上限 | 片段 p99 小不能抵銷 max 違反；不是完整固定集合的 p99，也不估計未來超標機率 |
| 片段 CPU 推進 | 30,569 個相鄰增量中 30,550 個為零，19 個為正且皆 15,625,000 ns（15.625 ms） | 只描述這次被停止片段；零值不代表沒有運算，19 個跳值不是 19 次獨立校準 |
| 既有 metadata | wall／CPU 的宣告 resolution 換算皆 100 ns，available／monotonic 為 true、adjustable 為 false | 證明當時保存了這些宣告；不證明實際每 100 ns 更新、精確度或誤差上界 |
| 片段純判定 | `q_ns=15,625,000`，診斷 status 為 `cpu_resolution_insufficient` | V65 算術對所提供片段的輸出；完整輪前提未成立，不能取代正式「未確認」 |
| 整關 wall | 1,942,445,700 ns（1.9424457 秒），含判定及必要 raw 落盤 | 這次提前停止後的完整收尾未逾 30 秒；不是完整三輪加十次 sleep 的完成時間保證 |

正式結論與片段診斷沒有互相覆寫。V66 要求完成 0.5 秒輪且正 CPU 增量至少十個，才可由該輪 p95 提前判能力不足；這次正式停止發生在 0.302 秒的 bracket 超標，因此保留 `clock_capability_unconfirmed`。這不等於 CPU 已足夠精細，只表示不能用未完成輪冒充原先要求的判定依據。

## 哪些結論目前可支持

| 編號 | 可支持的結論 | 目前不能延伸成的結論 |
| --- | --- | --- |
| F1｜工具行為 | V67 封存的 123 個合成案例全過；既有來源、原值、停止點與缺失可反讀 | 真實 timer 很準、很便宜，或 A 已涵蓋未來所有新來源／新邊界 |
| F2｜本次 B | 本次 max bracket 確定違反門檻，未完成規定流程；停止與不補跑符合計畫 | 只差一個慢點可以算通過；或任何新窗口都一定失敗 |
| F3｜CPU 片段 | 已觀測片段存在 15.625 ms 的正推進及大量零增量，沒有證據可發布 1 ms 細分能力 | 15.625 ms 是硬體精度、固定週期、所有環境的性質或量測誤差界；CPU=0 就是等待 |
| F4｜時間預算 | 該次停止與必要收尾在 30 秒內；raw／outcome 已保存 | 完整 B 必定在 1.9424 秒或 30 秒內完成；增加輪次／sleep 不會增加成本 |
| F5｜成本 | 既有 control 差可描述這一次收集、判定與保存所經過的 wall | 單次 API／探針淨成本、相對 O 的擾動、V46 解碼成本，或 C／D 已通過 |
| F6｜序位 32／33 | V67 沒有這兩筆的 query／分項同起訖 wall 與 CPU；原問題仍未解 | 用 dense 校準迴圈代表投票／正重疊，或回填 V47／V48 的等待時間 |
| F7｜原因與採用 | 目前只知道讀值窗口超標及片段 CPU 推進粗；V46 暫不採用 | bracket 是某背景程式／I/O／GIL／排程造成，或 V46 的完整入口變慢已被解釋 |

wall−thread CPU 仍只能稱有號殘差。依 V62，讀值時序、記帳量化、觀測成本與工作歸屬均可能影響它；即使未來工具通過能力與擾動驗收，也不能單憑正殘差區分 I/O、鎖、GIL、排程等原因。V67 的校準資料更不能替代歷史查詢所缺的起訖記錄。

## 收尾時間可以怎麼使用

既有四段 control wall 差相加恰為整關時間；它們不是 CPU 時間，也不是純函式耗時或可移除的成本：

| 既有控制區間 | wall 差（秒） | 邊界限制 |
| --- | --- | --- |
| metadata 前至純判定前 | 0.4124167 | 包含 metadata、片段收集與相關控制處理，不等於第一輪的 0.3019619 秒 |
| 純判定前至判定後控制點 | 0.9384062 | 包含當次判定與到下一控制點的工作，不能當 API 呼叫成本 |
| 判定後至必要 raw 寫入前 | 0.3236750 | 當次 snapshot 準備與控制點之間的工作 |
| raw 寫入前至寫入後控制點 | 0.2679478 | 含必要序列化、flush／fsync、hash 與到最後控制點的工作 |
| 合計 | 1.9424457 | 只對這次提前停止的 attempt 成立 |

這些值沒有 O／D 對照，也沒有完整 B 樣本數的等價基準。不能拿總時間除以 30,570 推成單探針成本，不能扣掉某段後稱新的「淨 wall／CPU」，也不能把節省保存時間當成已修復 CPU 推進或 bracket 限制。V67 並非因 30 秒耗盡而停止。
