# Stage 12｜V68 既有時鐘證據的能力限制與後續方案

本輪只整理 V67 已保存的紀錄與 V62／V66 事前規格，並評估後續路徑；不新增量測、clock metadata、測試、C／D 或原固定 48 筆重跑，也不改寫 V67 的結果。**V67 的唯一 attempt 不符合既定 B 條件，正式狀態維持 `clock_capability_unconfirmed`。目前不能發布 1 ms 尺度的細項 wall／CPU 判讀；也不能據此斷言任何環境都永遠無法量測。**維持暫不採用 V46，保留測試 locked。

## 收尾時間可以怎麼使用

既有四段 control wall 差相加恰為整關時間；它們不是 CPU 時間，也不是純函式耗時或可移除的成本：

| 既有控制區間 | wall 差（秒） | 邊界限制 |
| --- | --- | --- |
| metadata 前至純判定前 | 0.4124167 | 包含 metadata、片段收集與相關控制處理，不等於第一輪的 0.3019619 秒 |
| 純判定前至判定後控制點 | 0.9384062 | 包含當次判定與到下一控制點的工作，不能當 API 呼叫成本 |
| 判定後至必要 raw 寫入前 | 0.3236750 | 當次 snapshot 準備與控制點之間的工作 |
| raw 寫入前至寫入後控制點 | 0.2679478 | 含必要序列化、flush／fsync、hash 與到最後控制點的工作 |
| 合計 | 1.9424457 | 只對這次提前停止的 attempt 成立 |

這些值沒有 O／D 對照，也沒有完整 B 樣本數的等價基準。不能拿總時間除以 30,570 推成單探針成本，不能扣掉某段後稱新的「淨 wall／CPU」，也不能把節省保存時間當成已修復 CPU 推進或 bracket 限制。V67 並非因 30 秒耗盡而停止。

## 後續方案評估

**目前採取 P1：保留既有 wall／工作量／負載描述，停止 1 ms 細項 wall／CPU 歸因。**若仍要回答原本的 1 ms 問題，下一步優先做 P3 的候選觀測來源可行性規格，先確認有沒有值得量測的候選，再決定是否另立 B。這是根據既有缺口作出的工程取捨，不是替代來源已較準的實測結論。

| 路徑 | 可以回答的問題 | 缺的證據與負擔 | 本輪評估 |
| --- | --- | --- | --- |
| P1｜只用既有描述 | 已保存入口／query／分項在哪些配對較慢，及當時觀測到的工作量／負載關聯 | 缺 G5：沒有同起訖 CPU，不能拆等待，不能回填歷史原因 | **目前優先**；不新增量測。保留既有描述及 V46 暫不採用，不把關聯升格為原因 |
| P2｜同工具、另定窗口或環境的 B | 新窗口是否符合原 1 ms 目標要求的完整能力條件 | 缺 G1／G6：仍須完整輪與 sleep，且無證據換窗口能解決已見的粗 CPU 推進與 bracket；先固定新來源／環境、attempt、停止與預算 | **保留但非直接下一步**。不能稱補跑 V67，不能只換窗口重試到成功；先提出值得新量測的假設 |
| P3｜候選 CPU／觀測來源 | 是否有與研究範圍相符、可保存且可驗證的 CPU 或事件來源 | 缺 G3／G4：語義、歸屬、單位、更新／缺失、時序與接入尚待論證；可能需要改方法及受影響 A 案例，再驗新 B | **建議下一份規格的主題**。本輪未指定某個 API／平台，也未聲稱任何候選更精細；先做文件可行性評估，無法成立就暫不量測 |

### 目前不據以啟動的做法

不刪末點、不用片段 p99 或平均代替 max、不補跑到通過，也不將部分輪／null sleep 改成完整。延長時間、降低採樣密度、改序列化或先扣掉估計成本，都不是本輪證據已支持的修復；若未來要更動，須先說明方法與研究問題的關係並另版驗收。尤其 V67 的停止原因是 bracket，而非 30 秒用完，單從收尾分段挑最大耗時做優化，尚無證據能解決 CPU 推進或讀值窗口限制。
