# Stage 6 RFM 研究交付與適用說明

Stage 6 已整理為**離線研究交付**：Olist 的 v2／G2／五種子 G3，以及獨立 UCI Online Retail II 的 v1 資料建置、固定切點、跨期描述及清理敏感度均已完成。UCI v1 結果以本機 ZIP、逐檔清單與完整性收據封存；原報告、逐筆帳、切點及限制全部保留。

這是已檢視歷史資料的研究交付。正式客群行銷、流失／未來價值、淨營收及營運適用性尚未驗收。小組支援不足不因封存而解除。本輪只整理交付、核對既有檔案 bytes 並備份，沒有重建 RFM、重估切點、重算跨期指標或新增模型訓練。

## UCI v1 的固定研究設定

| 項目 | 已凍結內容 |
| --- | --- |
| T1 | [2009-12-01 00:00:00, 2010-12-01 00:00:00)，365 天，參考切點 |
| T2 | [2010-12-01 00:00:00, 2011-12-01 00:00:00)，365 天，固定套用後的回溯比較 |
| 歷史與截止 | 歷史起點 2009-12-01；各 T 先截前綴，再判表頭衝突、顧客母體及去重；S 包含、T 排除 |
| 主去重 | 八欄相同保留一列，來源表優先順序與列號固定；沒有明細鍵，不宣稱所有相同列都是錯誤 |
| 敏感度 | 單表最大出現次數、標準代碼形狀只篩 M、兩者合併，共三對照；不按後期挑最佳 |
| 缺值／取消 | 不補造顧客 ID；衝突購買發票整張隔離；取消與調整保留原帳，不用 C 尾碼配原單 |
| R／F／M | R 為整秒，F 為不同合格發票，M 為 0.001 GBP 整數單位正價明細毛額代理，可能含費用 |
| 零活動／未知 | 乾淨零活動 R=null、F=0、M=0；有本窗品質隔離時正式三欄皆 null，部分已知值獨立保存 |
| 切點 | 只用 main／T1 完整活躍 4,232 人，逆經驗分位數、同值不拆；三軸各五級，T2 重估 0 次 |
| 評估角色 | 全檔品質與月別金額早已檢視；後期是回溯描述，沒有完全未知保留測試或跨期通過門檻 |

完整切點與原始單位保存在跨期報告及私有 cutpoints.json；展示天數、英鎊格式只是轉換，不另建切點。

UCI 每期門檻為 `max(50, ceil(1%×完整活躍人數))`，本次皆為 50 人。八組資料每個單軸箱都達人數下限；125 種聯合組合仍不足以整體作細分行銷。沒有合箱、刪人、調門檻、重挑切點或挑敏感度口徑來改善結果。上述研究人數下限也不是統計效力或業務效益保證。

## 驗證與還原順序

```powershell
# 現有封存：讀回 ZIP 全部成員驗 CRC／SHA-256，另核 live 凍結研究檔。
.\.venv\Scripts\python.exe -B scripts\archive_uci_rfm_v1.py --verify
# 僅檢查 ZIP 與外層公開收據；適合來源尚未還原的情況。
.\.venv\Scripts\python.exe -B scripts\archive_uci_rfm_v1.py --verify-archive-only
```

封存工具只處理檔案／JSON 完整性，不匯入研究 runner，不解析 CSV 顧客值，不估切點或計指標。首次空白封存命名空間才用 `--archive`；有完整收據時只驗證，有部分產物則停止並保留，不刪檔重播。

還原時先保留 ZIP、外層公開收據與 `uci_rfm_release_v1/` 控制檔，再用對應版本程式執行 archive-only 驗證。使用乾淨的專案目錄，確認沒有同名或部分研究產物後，按 ZIP 中的專案相對路徑還原。這不是可直接覆蓋現有工作區的操作；封存工具本身不執行解壓或覆寫。

還原 `.venv` 與鎖定套件後，依序只讀驗證契約、資料及跨期結果：

```powershell
.\.venv\Scripts\python.exe -B scripts\freeze_uci_rfm_contract.py --verify
.\.venv\Scripts\python.exe -B scripts\build_uci_rfm_v1.py --verify
.\.venv\Scripts\python.exe -B scripts\run_uci_rfm_temporal_v1.py --verify
```

以上既有 `--verify` 多為來源／保存 bytes 核對；原始完整逐格核算與獨立統計驗收結果仍以各輪收據為證。不要把 hash 檢查說成重新跑完原研究。若檔案缺漏或 hash 不同，先處理還原／版本問題，不重訓或重新估切點來補證據。
