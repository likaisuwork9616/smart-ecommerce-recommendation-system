# Stage 4：只新增主賣家未觀測交運待件件數

前輪[固定三模型診斷](STAGE4_COMMON_MISSES_AND_SIGNALS.md)找到1,210張共同漏報，並確認核准時點可回溯兩個待交運代理。本輪只測其中的件數，不加入時齡p90，也不改預測時點、訓練目標、正則化、配對設定或提醒預算。

## 唯一變動與資料時點

| 項目 | 本輪設定 |
| --- | --- |
| 對照 | 原101欄 `xgboost_rank_backlog_7_14d_l2_100_topk_10` |
| 新候選 | 原101欄＋`seller_unobserved_handover_pending_count_90d`，共102欄 |
| 不同於先前102欄 | 先前加的是已完成交運事件數；本輪加的是尚未觀測交運或送達的歷史待件件數 |
| 固定參數 | 核准時點、seed42、L2＝100、原生topk10及原樹參數／前處理規則 |
| 訓練與資料 | 八個月份新fit；原101欄八個版本重播，成熟訓練列、穩定排序與每日query保持相同 |
| 提醒 | 每個已結束完整日排序，按`floor(0.1×N)`取名額，未知答案先參與競爭，不另給子群預算 |
| 選模 | 前78候選指標凍結，加1候選共79，仍只依歷史驗證規則選模 |

對每張訂單的核准時間t，先依最高品項單價`price`、再依最低品項序號找主賣家。同賣家的其他歷史訂單須有有效的購買≤核准時間，且核准落在`[t−90天,t)`。當實際交運、送達事件都尚未嚴格早於t，才計入待件；等於t仍未觀測。已觀測的矛盾事件不納入待件，也不讀最終狀態、評論或未來送達來提前篩選。

已知主賣家沒有待件時記0；主賣家缺失則留缺值，不能把不同未知賣家合併。沒有五筆事件的最低支援門檻，也不增加時齡、分位數或手工缺失指示。原有訓練補值與缺失指示規則維持；新輸入會使樹重新學習，特徵抽樣與擬合結果可能改變，不能將個別提醒交換解釋為單一特徵的因果作用。

這仍是「未觀測事件」代理，沒有取消、事件登錄與品項版本時間來確認實體是否出貨；靜態主賣家映射在核准時可知也是資料假設。已觀測交運但尚未送達的在途件不計入，因此與既有未送達待件也不同。

## 評估與診斷方式

沿用原70,844筆、137欄快取，保留全部原值，只新增一欄成138欄。快取含標籤及診斷欄，與模型101／102欄白名單不同；已完成交運的三個欄位雖留在快取，均不進新102欄輸入。所有查詢嚴格早於2018-05-01，不替原保留測試建新特徵或重評分。

九個歷史phase保留各fold月初的實際送達答案截止；同一月份可因答案成熟時間不同而重複出現，不能合併成獨立樣本。2017-12、2018-02、2018-04為互不重複但已反覆檢視的開發回測，不能當未知測試。各月完整日分數先排名取容量，再計已知答案指標；排名分數為sigmoid(raw margin)，不是校準後延遲機率。

固定候選比較與歷史選模主方案分開呈現。適用要求仍檢查歷史各月至少30%召回，開發結果不進選模鍵，也不自動取代預設原版Random Forest。

診斷保留全部路線、承諾天數、日量與件數分箱的補抓／新增漏報，以及前輪三模型共同漏報群體的恢復數。共同漏報先由前輪101／已完成交運102／104欄定義，再查看新模型；不能用本輪分數反過來改群體。不同維度重疊，各子群不重新排名，也不各分10%。提醒流入／流出是數量記帳，不代表特定準時件直接擠掉特定延遲件。

## 重現方式

使用專案`.venv/`，不需要新增套件或MySQL操作：

```powershell
.\.venv\Scripts\python.exe scripts\delay_unobserved_handover_features.py
.\.venv\Scripts\python.exe scripts\train_unobserved_handover_count.py --specification-only --n-jobs 2
.\.venv\Scripts\python.exe scripts\train_unobserved_handover_count.py --n-jobs 2
.\.venv\Scripts\python.exe scripts\diagnose_unobserved_handover_count.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

新快取、分數、模型與本機驗證留在Git忽略路徑。特徵腳本從原始訂單／品項重建件數，核對既有137欄快取的SHA與前後原值；訓練前固定規格，既有候選與來源沿用前輪報告及模型。該特徵腳本的來源雜湊也納入規格，因此以`.gitattributes`固定該檔為LF，避免Windows Git換行轉換改變驗證值。若執行中斷、尚無完整報告，可明確使用`--reuse-new-versions`重用已完成且來源相同的自有月份版本；重用不算新的fit。完整報告已存在時，CLI會拒絕覆寫。需重做完整訓練時，另設新的Git忽略輸出目錄，先把138欄快取放在該目錄的`data/olist_delay_unobserved_handover_features.csv`，再以`--output-dir`指定；不覆寫本輪證據。
