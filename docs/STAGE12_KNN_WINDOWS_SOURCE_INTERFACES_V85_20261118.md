# V85｜跨程序時鐘與鎖檔身分介面封存

本輪準備 QPC／QPF 及從原 `fd` 取得 FileIdInfo 的獨立介面和假案例。驗證範圍涵蓋語法樹、來源、案例名單及原封存反查。使用者本輪授權封存，案例、原生 API、實機量測與正式窗口均未執行。[V84 候選規格](STAGE12_KNN_WINDOWS_LOCK_SOURCES_V84_20261118.md)

## 第一步：獨立介面

| 介面 | 封存範圍 |
| --- | --- |
| QPC／QPF | 從明確注入的來源收集整數 tick 與頻率。樣本保留主機、開機、擷取、OS、runtime、adapter 與程序標籤，API 失敗保留呼叫名稱與可用錯誤碼。區間轉換要求外部提供共同域、頻率、共同原點及取樣誤差界線，每側額外保留一個原生 tick 並向外取整 |
| 同一 `fd` 的 FileIdInfo | 介面接受原已開啟的 stream 與 `fd`，以注入來源借用 handle，檢查開檔識別前後相符。解讀完整 64 位元磁碟區序號及原序 16 bytes 的檔案 ID。角色與本機 provider 由外部證據綁定，同一世代的判定另需共同擷取範圍、canonical 路徑和世代連續證據 |

兩個介面只有注入式後端，沒有 Windows API 綁定或預設來源。時鐘與檔案結果只表達各自的來源與界線。跨程序可比資格及 `budget.guard` 世代證據仍要另驗，V82 的鎖持有者判定須在兩者及角色、範圍與事件覆蓋都成立後才可使用。

## 第二步：假案例與來源封存

| 核對項目 | 結果 |
| --- | --- |
| 10 個時鐘案例 | 覆蓋原始高位 tick／Hz、失敗、逆序、頻率變更、共同原點、來源與角色不相符、向外取整、區間相等及一 tick 歧義。以 V83 的純判定函式編寫假持鎖區間的正負例 |
| 13 個檔案身分案例 | 覆蓋 32／64 位元 handle、高位序號、原序 ID、借用前後 fd 與 handle 檢查、無效值、同次 API 錯誤與缺碼、未核路徑、provider 與檔案世代不一致 |
| 封存方式 | 對來源做 AST 解析及 import 路徑核對，逐項對照案例中的參數、預期分支和 23 個方法名單。記錄兩個介面、案例檔及既有 V83 純判定相依檔的位元組數與 SHA-256 |
| 原結果與 golden | 38 份 V80 方法來源描述、34 個方法、196 個子案例、24 族、3 份人工來源 manifest 及其 78 個檔案逐一反核。A12 原 golden 與封存相符，V80 收據仍為 147 通過、1 失敗、48 未執行 |
