# V85｜跨程序時鐘與鎖檔身分介面封存

本輪依 [V84 候選規格](STAGE12_KNN_WINDOWS_LOCK_SOURCES_V84_20261118.md)準備 QPC／QPF 及從原 `fd` 取得 FileIdInfo 的獨立介面和假案例。驗證範圍到語法樹、來源與案例名單。使用者本輪授權封存，案例、原生 API、實機量測與正式窗口均未執行。

## 第一步：獨立介面

| 介面 | 封存範圍 |
| --- | --- |
| QPC／QPF | 從明確注入的來源收集整數 tick 與頻率。收據分開保存來源域、程序身分和 API 錯誤。區間轉換要求外部已提供共同域、頻率及共同原點，再保留至少一個原生 tick 的邊界並向外取整 |
| 同一 `fd` 的 FileIdInfo | 介面接受原已開啟的 stream 與 `fd`，以注入來源借用 handle，檢查開檔識別前後相符。解讀完整 64 位元磁碟區序號及原序 16 bytes 的檔案 ID。磁碟區、檔案世代、角色與本機 provider 的資格值由外部證據提供 |

兩個介面只有注入式後端，沒有 Windows API 綁定或預設來源。時鐘與檔案結果只表達各自的來源與界線。跨程序可比資格及 `budget.guard` 世代證據仍要另驗，V82 的鎖持有者判定須在兩者及角色、範圍與事件覆蓋都成立後才可使用。
