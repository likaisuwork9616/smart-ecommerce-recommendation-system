# Stage 6：v2 RFM 五種子 G3 方法敏感度

本輪承接 [v2 重建與真實 G2](STAGE6_RFM_REBUILD_V2.md)，依[原評估規格](STAGE6_RFM_EVALUATION_SPEC.md)執行五種子同快照方法敏感度。原 RFM、G1、G2、61 份來源與先前公開結果保持原 bytes；G3 使用獨立的 `.runtime/stage6_rfm_g3_v2/` 保存私有證據，不回寫舊報告中的當輪狀態。

## 固定方法

| 項目 | 本輪執行規則 |
| --- | --- |
| 參考母體 | 同一 S=2017-09-01、T=2018-09-01 快照的 72,124 位完整活躍顧客，依 customer_unique_id 升冪 |
| 原 G2 參考 | R／F／M 為 5／2／5 級；50 個組合中 25 個支援不足，涉及 1,791 位回購顧客 |
| 五種子 | 固定 11／29／42／73／101，不挑最好種子 |
| 抽樣 | 各取 `sample_n=(4*n)//5=57,699` 位，不放回；`Generator(PCG64(seed)).choice(n, size=sample_n, replace=False)` |
| 切點 | 只在各抽樣顧客估原尺度 P20／40／60／80；精確整數 rank、同值不拆、重複去重、移除 ≥抽樣最大值的切點 |
| 比較母體 | 抽樣切點套回同一完整 72,124 位參考顧客；不是只比較抽中者，也不是保留測試 |
| 級數與人數 | 每軸 2–5 級且與參考同級數、無空箱，每箱至少 361 人；分母採完整參考人數 |
| 每軸一致率 | 每種子、每軸的同 ID 序數一致率皆須 ≥0.90；級數不同時列 null／不可直接比較，並判不合格 |
| 組合 ARI | 各分區將三軸 tuple 一對一編成一維標籤，同 ID 順序計算 ARI；每種子皆須 ≥0.80 |
| 退化與小組 | 單群／每人一群即使 ARI=1 也不合格；小組低於 361 人另標支援不足，不合併、不宣稱該組穩定 |

沿用鎖定 NumPy 2.5.4、scikit-learn 1.9.1 與 Python 3.12.10。上述門檻是原專案的事前研究規格，不是通用統計標準或營運收益保證。

## 驗收與保存

先重新執行 v2 完整只讀驗證，取得與來源及私有 output guard 綁定的新驗證收據；沒有重建資料集、重跑 G1 或 G2。G3 新增來源、核心、輸出反讀與入口，加兩套測試，共固定 69 份來源。

本輪 26 項合成測試全部通過（7.618957 秒），0 error／failure／skip。測試包含固定抽樣、同值不拆、級數改變、90% 門檻邊界、樣本限定切點、零元／大整數金額、單群／單人退化、tuple ARI 與各軸 ARI 平均的差別、完整 ID／抽樣／分配竄改、來源變更、部分輸出及最後 guard 寫入失敗。完整 test IDs 與實際耗時保存在[事前規格](../reports/stage6/rfm_g3_v2_specification.json)，測試不是真實效能成績。

獨立反讀程式不呼叫 G3 核心或 scikit-learn ARI：它依相同固定 RNG 核對已保存抽樣位置，以另一套精確 rank／判界運算驗每位顧客分配，再用整數列聯表與有理數 ARI 核對結果。ARI 浮點反讀容差預先固定為 1e-12；其他公開聚合及私有 ID、bool、整數、null 逐值比對。重新核對既定抽樣是驗收，不是新增種子或另一輪選模。

現有完成版本只使用：

```powershell
.\.venv\Scripts\python.exe scripts\run_rfm_g3.py --verify
```

不需真實資料的合成測試：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_rfm_g3 tests.test_run_rfm_g3 -q
```

`--prepare` 和 `--run` 是本輪一次性操作，既有版本、部分輸出或 failure 都會阻止重播。公開 JSON 存在不能單獨代表完成，還須有效外部 output guard、無 failure 並通過完整反讀。若某個種子不合格，仍保存完整診斷，不同輪換種子、切點或門檻直到通過。

### 本機完整備份

`.runtime/backups/stage6_rfm_g3_v2.zip` 包含本輪必要程式／規格、原始四表、v2 資料／G1／G2 私有鏈，以及 G3 的抽樣位置、分配、manifest、測試 log 與控制檔。逐檔 CRC／SHA-256 反讀紀錄保存於 `.runtime/verification/rfm-g3-backup.json`；原 v2 ZIP 保留，沒有覆寫。

還原時使用相同版本的乾淨 checkout，先確認沒有既有或部分 v2／G3 私有輸出，核對 ZIP 中 `rfm_g3_v2_backup_manifest.json`，再依專案相對路徑還原；建立 `.venv` 並安裝鎖定套件後執行 `scripts/run_rfm_g3.py --verify`。備份含個體資料，維持 Git 忽略；未包含服務憑證、MySQL 或 `.venv`。目前只保存在同一磁碟，尚未另存異地。

## 來源與文件檢查

本輪固定的 69 份來源核對一致。執行前 531 份既有檔案中，只更新 7 份導覽／屬性檔，其餘 524 份 bytes 保留，包含 v2 程式、正式 JSON 與既有結果文件。81 份 Markdown 的 1,101 個本機檔案連結皆存在；未把檔案連結檢查稱為頁內錨點驗證。新增公開報告沒有個體 ID 或本輪私有輸出 digest。詳細紀錄位於 `.runtime/verification/rfm-g3-publication.json`。

## 解讀與下一步

五次抽樣共用同一份最終快照，沒有新增獨立時間資料，不是信賴區間，也不是訓練、開發回測或最終保留測試成績。即使 G3 通過，小組支援不足的限制仍保留；M 仍是商品毛額，不代表淨收入或未來顧客價值。

下一步應取得第二個時間快照及完整顧客名冊、來源版本／入庫時間、觀察完成與金額對帳證據，再驗跨期穩定性或特定業務用途。資料未到前，將本輪整理為同快照研究交付，不追加種子挑結果、不命名 VIP／流失群組，也不自動進入行銷或部署。Stage 4、5 繼續待資料，每日 10% 延遲提醒預算與 Dashboard 暫緩安排維持。
