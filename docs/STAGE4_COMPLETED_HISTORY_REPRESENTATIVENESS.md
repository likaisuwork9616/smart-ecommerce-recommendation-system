# Stage 4：完成歷史對未完成慢件的代表性稽核

承接[固定條件成熟訊號比較](STAGE4_CONDITIONAL_MATURE_SIGNALS.md)，本輪區分原來的「最近完成事件」與「同一批最近核准訂單」。沿用原101／時齡102 × colsample 0.8／1.0、11／29／42／73／101五種子、完整日10%提醒與凍結漏報身分；沒有載入、重播或訓練模型。

**本輪決定：不指定單因子訓練，新增fit為0。** 完成歷史與待件確實涵蓋不同組成，但缺口沒有直接證明能區分共同漏報。固定精確承諾與核准星期後，二月SP→RJ支援充分涵蓋為0；等待組路線比例只剩4張、1週。六個比例在五焦點均未通過單月及跨月事前篩查，不能把稀疏造成的未通過解讀為訊號已證實無效。

## 事前定義與資料時鐘

原成熟歷史依送達事件取`[t−W,t)`；新稽核先取核准事件落在`[t−W,t)`的原始訂單，再看核准當下`t`已觀測到哪些事件。兩個窗口都左含右不含，但代表不同母體，不能把完成窗口與待件窗口直接相除。

| 項目 | 固定定義 |
| --- | --- |
| 查詢 | 原70,844筆175欄、核准時間早於2018-05-01；原欄與查詢順序保留 |
| 原始歷史資格 | 購買與核准有效、購買≤核准、核准早於2018-05-01；不以最終狀態篩選 |
| 分組 | 主賣家90天、完整州路線90天、賣家×路線90天，以及路線30天背景 |
| 主賣家／路線 | 沿原最高商品價、最小商品序號與靜態賣家州→顧客州；仍有主檔可得性假設 |
| 完成 | `approval≤delivery<t` |
| 已觀測異常 | `delivery<approval`且`delivery<t`，另列，不混為正常完成 |
| 待完成代理 | 沒有送達事件嚴格早於`t`；不等於實際未送達、最終延遲或取消 |
| 邊界 | `delivery=t`在歷史特徵仍未觀測，列入待完成並另計邊界；沒有重算提醒資格或名額 |
| 承諾 | 承諾日非空且不早於核准日才有效；日末截止為承諾日午夜加一天 |
| 逾承諾 | 有效承諾且`deadline≤t`，仍待完成；其餘分未逾與承諾無效 |
| 承諾無效 | 缺失與負承諾天數分開列，不當作準時 |
| 未觀測交運 | 待完成者沒有任何`carrier<t`事件；沒有紀錄不等於證明未寄出 |
| 未來資訊 | 2018-05-01起的送達／交運事件先遮蔽，每個查詢再遮蔽所有`event≥t` |
| 最終完成cohort | 以原70,844身分標記legacy資格，僅供事後排除量與舊欄對帳，不決定新母體或比例 |

每筆查詢都對帳：核准總數＝完成＋待完成＋已觀測異常；待完成＝未逾承諾＋已逾承諾＋承諾無效。另有原成熟窗口橋接：**原legacy送達窗口＝同核准窗口內legacy完成＋更早核准但最近完成**。最後一項不是新核准窗口的完成件。

兩個主要稽核比例為`待完成／同核准窗口總數`及`有效承諾逾期待完成／同核准窗口總數`，不加先驗。未知key或核准總數為0時比例缺失，不能填成0。歷史窗口在不同查詢間重疊，總出現量不是獨立訂單量；另列每個基礎實際涵蓋的不同歷史訂單數。

## 固定條件與比較

比較固定的是**目前查詢**的路線、承諾、核准週與原成熟支援量；沒有把每張歷史訂單自己的承諾與時齡也配成相同。因此另報完成與待完成者的承諾天數及時齡組成，不把組成差異直接當成漏報原因。

| 固定項目 | 規則 |
| --- | --- |
| 群組 | 原16群：ALL、R、A、RA、R不含A、A不含R、非A、SP→SC及八個R/P/A互斥格 |
| A | 主賣家歷史未觀測交運待件時齡p90在`(24,72]`小時；不是本單等待後再預測 |
| 主要對照 | 全20同身分共同漏報，對同格全部已知準時件；次要為其他已知延遲 |
| 三種規格 | 原承諾分箱；精確承諾天數；精確天數再加週一0至週日6的核准星期 |
| 週與支援 | 週一00:00起算；賣家用seller90、joint用joint90、路線用route30與route90原成熟支援分箱 |
| 覆蓋門檻 | 有限值漏報／對照各≥1；格內漏報≥3且對照≥5；再要求每個相應成熟本地支援≥20 |
| 分母 | 所有共同漏報保留，未涵蓋互斥拆成缺值、無對照、格內樣本少及本地歷史不足 |
| 權重 | 同格均值差與排序率按有限漏報筆數加權，對照標準化到相同組成；另報每格等權 |
| 排序 | 稽核比例較高記作+1假說方向，絕對差≤1e−12同分算半分；不是模型AUC |
| 種子／階段 | 原12phase各自答案截止，五焦點保留五seed自己的四模型共同漏報；不合併重複驗證月 |
| 公開格 | 二月開發月五焦點保留三規格、六比例的完整觀測格；其餘phase保留摘要與週別 |

歷史時齡一律為`t−approval`，兩種狀態都使用相同時鐘。固定分箱`[0,7)、[7,14)、[14,30)、[30,60)、[60,90]`天；30天窗口最後為`[14,30]`。待完成時齡只是最終耗時下限，不以未來送達補齊，也不拿它當完整配送耗時與完成件比較。

事前探索篩查要求三規格各涵蓋至少20張支援充分漏報、跨至少3週，均值差與排序率方向同向、全部五種子同向，且在兩個不同開發月同向。正反向都保留；通過也不代表新訊號、顯著性、因果或可部署。

## 原有訊號與來源保護

原101已包含seller／route待件量、逾期待件量、待件對完成量比例、逾期待件占比與7／14天變化。代表性缺口不是新訊號的充分證據，本輪先作不讀標籤的逐值重複與Spearman檢查，不從相關低或單月差異直接選特徵。

四個原成熟件數、三個待件數及三個逾期待件數逐筆重建。原逾期計數會納入負承諾天數，本輪將它另外列出；「本輪有效承諾逾期待件＋負承諾待件」應精確還原原欄，沒有修改既有特徵。

事前規格綁定235個來源及3份新分析程式SHA；正式執行前後重驗。新增124個稽核欄只存於本機299欄快取，不加入任何模型白名單。原完成cohort的最終狀態是回溯資訊，不能稱為當時已知。

發布前發現公開metadata的tuple會在JSON重讀後變成list，導致同內容重跑被誤判不同。初次執行由程式SHA保護中止、未產正式報告，也未檢視新條件對照結果；保留[初版規格](../reports/stage4/completed_history_representativeness_initial_specification.json)，只修正metadata格式並加入完整phase／screen的JSON roundtrip測試，再凍結正式規格重跑。計數、分格、權重及門檻未變。
