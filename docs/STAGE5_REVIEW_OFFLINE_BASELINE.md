# Stage 5：四欄離線最小基線

本輪將[已驗證的四欄pipeline](STAGE5_REVIEW_PIPELINE_IMPLEMENTATION.md)接到既有來源守門、H60標籤及完整角色名冊，依[凍結基線規格](STAGE5_REVIEW_BASELINE_SPEC.md)執行常數參照與L2 Logistic。這是2017-12、2018-02、2018-04三個已檢視月份的開發回測；結果不代表新未知保留測試或正式營運驗收。Stage 4維持待資料、每日10%及11／29／42／73／101五種子，Dashboard暫緩。

## 來源與角色守門

執行前須有原Olist九CSV、原H60私有bundle、原正式執行收據及基線input_guard。程式核對凍結資料集／基線規格、報告、manifest、原收據、來源SHA與鎖定套件版本；不重寫舊標籤或重建guard替不相符資料背書。新執行規格另存，舊凍結來源保留原bytes。

原orders只解析order_id、購買、核准三欄；按既有規則重建73,254張研究核准名冊，再逐ID、核准時鐘及canonical順序核對C名冊與12個角色。完整角色共289,973列是歷史訂單跨角色重用，不能當作獨立樣本數。不可只檢查列數，或讓raw與membership共同漏單而互相通過。

訓練讀自己的角色標籤，嚴格要求`t+60天<fit`與首答在`(t,t+60天]`且早於fit。未知保持NA，只讓合格y進前處理及模型。查詢則使用完整名冊，傳入pipeline的七個未來標籤欄先清空；保留的role truth另供事後計分，不影響出分資格或X。C截止的全域標籤不能回填歷史fit。

上述驗證只能證明既有快照及凍結研究名冊一致。原業務入庫、評分修訂、購買／核准版本與業務時區仍缺證據，不能據此宣稱核准當下營運可用。

## 固定方法與執行順序

| 項目 | 本輪依循規格 |
| --- | --- |
| 目標 | 核准後60天內首個記錄回答：1–2分對3–5分；無答、超窗、品質隔離及未成熟均未知 |
| 四欄 | 購買月、星期、時與原核准等待小時；43個固定one-hot類別＋train-only標準化等待，共44維 |
| 前處理 | 只fit合格訓練列；每個C及外層重建，無補值、log、clip或主檔／評論特徵 |
| 主模型 | L2 Logistic，C=0.1／1／10；固定lbfgs、tol=1e-8、max_iter=1000及既有其餘參數 |
| 常數參照 | 同次fit合格訓練低評比例，不平滑、不參與C選參 |
| 內層 | 驗證月依序2017-09／2017-11／2017-12，以各自role合格y計非插值AP；距最大AP≤1e-12取最小C |
| 外層 | C固定後，在2017-12／2018-02／2018-04月初從頭fit，對各月完整名冊出分 |
| 失敗 | 任一候選失敗、ConvergenceWarning、非有限係數／機率／AP或所需角色缺類別即停止，不縮候選或自動改參數 |
| 計分 | 只用各query角色合格y；逐月AP、ROC-AUC、Brier、固定logloss及p≥0.5混淆表，unknown不填負例 |
| 彙總 | 三外層月AP均有效才計等權macro；無pooled AP、獨立fold信賴區間、門檻選擇或校準 |

Stage 5固定random_state=42僅供重現，沒有五種子比較或每日預算排名。Stage 4原有每日10%與五種子政策不延伸成這輪評論模型的效能要求。

## 交付與重現

公開交付[來源loader](../scripts/review_baseline_sources.py)、[訓練入口](../scripts/run_review_baseline.py)、[評估函式](../scripts/review_baseline_evaluation.py)、兩組合成測試、新執行規格與聚合成績。私有輸出放`.runtime/stage5_review_baseline_training_v1/`：

| 私有檔案 | 實際內容 |
| --- | --- |
| input_guard.json | 新規格實際bytes及5份既有私有來源綁定 |
| inner_scores.csv | 17,528張角色查詢×3個C與1個常數，共70,112列 |
| outer_scores.csv | 19,316張查詢×選定Logistic及常數，共38,632列 |
| fit_audit.json | 12次fit的合格ID、類別支援、scaler統計與係數；不公開、不作服務模型 |
| manifest.json | 規格、guard、公開報告及三個私有產物的版本綁定 |

合計18組出分區塊、108,744列是跨候選／角色的出分次數，不是獨立訂單數；每列15欄。CSV以17位有效數字輸出，1,631,160個cells反讀一致，包含float64機率及nullable y。沒有模型序列化、正式提醒名單、API、Dashboard或營運核准。

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_review_baseline_sources tests.test_review_baseline_training -q
.\.venv\Scripts\python.exe scripts\run_review_baseline.py --specification-only
.\.venv\Scripts\python.exe scripts\run_review_baseline.py
```

`--specification-only`只驗來源並凍結本輪規格／guard；正式命令才fit。已有任何正式結果或failure receipt會在fit前拒收，不可為驗證而無意重訓。所有輸出路徑及來源衝突先檢查，各fit前後核36個綁定（29公開來源、5舊私有來源及本輪規格／guard）；全部輸出預檢與反讀通過才留下完成報告。失敗會記階段、fold、C及已完成fit數，沒有fallback；晚期檢查失敗只撤回本次新寫且bytes仍吻合的公開報告。

重現需要原私有資產；Git clone不會附帶原資料、角色CSV、原收據或guard。缺任一必要來源即停止，不能自行補寫通過證明。若要另一次訓練，需明定新的執行版本與私有輸出位置，不能刪舊證據來繞過拒收。

## 限制與下一步

本輪只能評估固定窗內具有合格首答的訂單。未知／未回覆者雖完整出分，仍沒有可驗證y；不能把已知子集成績外推全部核准母體。滾動fold會重用歷史訂單及客戶，三月已檢視，不能視作獨立重複或新未知測試。

後續已完成[凍結分數與四欄支援診斷](STAGE5_REVIEW_SCORE_DIAGNOSTICS.md)：沒有追加fit或重預測，原結果保持不變。新文件記錄月份類別支援、逐月低評率／分數分布與下一輪消融假說。

當輪建議的下一步是只讀凍結分數與既有四欄來源，核對各月低評率、分數分布及訓練／查詢支援差異，優先釐清2018-02排序低於參照、4月機率損失較差的現象。後續診斷已完成，結果與單因子假說見上方連結；原入庫／版本缺口仍需新證據才能處理。
