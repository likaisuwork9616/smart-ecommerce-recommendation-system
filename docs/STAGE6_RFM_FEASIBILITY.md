最大事件不是watermark／日結或完整月證據。原始最終狀態有96,478張delivered，但不表示它們都在T前完成；也不能因目前已取消，反推T時已取消。原[Stage 3 SQL](../sql/03_business_analysis.sql)的月營收／AOV只用最終delivered且無T截止，不能直接當歷史RFM。

候選訂單以一單一列，要求：購買位於`[S,T)`、快照最終status=delivered、購買與送達可定位且`purchase≤delivery<T`。再獨立核顧客映射、明細鍵與商品金額支援。核准不是本候選資格必要欄，不沿用Stage 5核准／H60母體；明細／付款列數或分期數也不是訂單數。

候選輸入支援為**74,147單／72,183個匿名顧客鍵**，其中明細、付款與運費均有合法資料；這不是已產生的RFM名冊或營運覆蓋。另有59張候選單的送達早於核准，原程式只列品質旗標，沒有偷偷額外剔除；下輪須在資格契約中明定其處置。`orders_with_missing_approval`指缺或無效核准，本候選為0。

## 金額口徑與join

| 口徑 | 候選規則與限制 |
| --- | --- |
| 主M候選 | 同一合格訂單集合的item.price合計，命名「商品快照毛額」；沿既有專案的BRL名目單位，不作匯率、會計幣別或淨營收驗收 |
| 運費 | freight_value獨立合計；商品含運是另一種口徑，不混入主M、不與舊SQL的revenue欄混稱 |
| 付款 | payment_value先獨立按order_id合計，只作對帳；payment_installments不是乘數，付款列數不是F。零付款或voucher亦不證明實收現金 |
| 金額精度 | Decimal轉整數分，拒絕缺失、NaN、非法精度與溢位；負值另列品質，不補0、不用付款回填缺商品金額 |
| 退款／更正 | 沒有退款、退貨、折讓、settlement與原交易／版本時鐘；不能稱淨實收、淨營收、利潤或T時已知消費 |

明細與付款必須**各自先聚合成每單一列**，再以訂單母表受控left join並保留缺流／隔離旗標。全來源同時有兩流的98,665單中，275單兩流都多列；若直接join明細×付款，會展成117,601列。這個98,665是雙流inner join的對照母體，不是全來源訂單分母。

| 同單對帳 | 全來源雙流可比訂單 | 候選窗口支援訂單 |
| --- | ---: | ---: |
| 可比訂單 | 98,665 | 74,147 |
| 付款精確等於商品＋運費 | 98,089 | 73,708 |
| 付款不相等 | 576 | 439 |
| 付款較高／較低 | 367／209 | 262／177 |

候選商品毛額合計10,174,756.38、運費1,711,057.33、付款11,887,604.63，差額合計1,790.92；皆為該候選集合的來源總額，不是個體M或營收成長。逐單差額原因未驗證，不能強迫兩流相等、任選較大值或以一分差當已核准業務容忍。

## R、F、M尚待凍結的資料集契約

| 面向 | 建議方向 | 下輪需先決定 |
| --- | --- | --- |
| R | 同一資格集合中，T減最近購買時間；購買代表交易行為，若改送達需另名定義 | elapsed days是否保留小數／取整、無合格訂單時R為未知而非自行填0或無限大 |
| F | 同一`[S,T)`的distinct order_id | 視窗長度、是否只含完成交易、時鐘異常與取消／退款處理；不把明細／付款／分期數當F |
| M | 同一集合商品快照毛額，運費／付款另保留對帳 | 是否接受毛額研究、缺明細與修訂處理；不混商品、含運、付款或假造淨額 |
| 顧客母體 | 以匿名unique_id彙總，但不使用T之後才出現的顧客補名冊 | 只含窗口活躍買家，或T前歷史客戶含零活動者；窗口外／無合格訂單不可直接刪除後宣稱涵蓋全部顧客 |
| 分群 | 本輪未定義 | 不產生分位數、RFM分數、群名、群界、KMeans或業務成效；需資料集與驗收先完成 |

早期左截斷、後期未送達、不同顧客可觀察歷史長短與缺流，均影響RFM解讀。單一快照描述性分群也不等於未來回購／流失預測；若日後要驗證行動成效或預測，須另外切未來答案與處理曝光紀錄。
